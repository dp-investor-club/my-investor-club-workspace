# 카드 03 — 선판단 후대조: 시장 반응을 보기 전에 내 판단을 먼저 적는다

## 어떤 병목에서 나왔나

"거시 지표를 그때그때 수기로 찾기 바빴고, **시장 평균 반응이 어떤지 몰랐다.**"
"지표 발표 수치만 보고 내가 판단을 내리기엔 막막했다."

같은 주에 두 사람이 서로 다른 스킬에서 같은 구조에 도달했다.

## 원래 시도

- 한쪽: 매일 지표를 트래킹하는 자동 수집을 붙이려 했다.
- 다른 쪽: 컨센서스는 "남의 생각"이니 신경 쓰지 않고 내 판단만 기록하려 했다.

## 무엇이 바뀌었나

두 개의 깨달음이 각각 방향을 틀었다.

- **트래킹 빈도가 아니라 판단 시점이 문제였다.** 거시 지표는 발표일 사이에 시차가 있어 이벤트성이 크다. 매일 볼 일이 아니라 **발표일에 한 번 제대로** 볼 일이다.
- **컨센서스는 판단을 대체하는 게 아니라 판단의 보조 지표다.** 배제할 것이 아니라 편입할 것이었다. 단, 순서가 중요하다.

## 지금의 구조

순서가 이 카드의 전부다.

```
발표일 아침, 작업실을 열면
  1. "오늘 OO 발표일입니다. 의견을 먼저 적어주세요"  ← 내 판단이 먼저
  2. 내가 적는다 (예상 방향 + 이유)
  3. 그다음에 수집된 시장 반응 · 컨센서스를 연다
  4. 내 판단과 대조해 공통점 / 차이점을 기록
  5. 나중에 실제 결과로 다시 대조
```

3번을 1번보다 먼저 하면 이 구조는 무너진다. 남의 숫자를 먼저 보면 내 판단이 거기에 끌려간다(앵커링). **"먼저 적고 나중에 개봉"이 장치의 본체다.**

## 내 스킬에 붙이는 방법 (단계 1개)

기존 수집 스킬 맨 앞에 단계 하나를 끼운다.

```markdown
### 0단계 — 내 판단 먼저
수집 결과를 보여주기 전에 사용자에게 묻는다:
"이번 건 어떻게 볼 것 같으세요? 방향과 이유를 한 줄로."
답을 기록한 뒤에만 다음 단계로 간다.
```

그리고 마지막에 "내 판단 vs 실제" 한 줄 대조를 붙인다. **틀린 기록이 남는 것이 이 구조의 목적이다** — 맞추는 게 목적이 아니다.

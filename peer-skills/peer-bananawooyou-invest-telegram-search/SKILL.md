## 이 스킬은
- 어떤 병목: 리포트가 흩어져 올라오는 텔레그램 채널을 하나씩 열어보며 스크롤하느라, 정작 리포트 본문은 못 읽고 캡션 요약만 보고 판단하게 되는 것
- 입력 → 남는 것: 종목명 하나를 말하면 → 여러 채널을 동시 검색해 최신순으로 병합하고, 첨부 PDF 본문까지 읽어 **증권사별 투자의견·목표주가 비교표 + 추정실적 비교표**를 출처 라벨과 함께 남긴다
- 설치 후 첫 실행: "텔레그램에서 에이피알 리포트 찾아줘"
- **아직 안 되는 것: 설치가 필요하다.** 프로그램(`server/`)은 이 폴더에 함께 들어있지만, **본인 텔레그램 계정 로그인**을 한 번 해야 하고, 검색되는 채널은 **본인 계정이 이미 가입한 채널뿐**이다. 아래 설치를 통과하지 못하면 도구 자체가 안 잡힌다 — 그 실패 지점이 원저자에게 줄 데이터다.

# telegram-search

애널리스트 리포트 등이 올라오는 여러 텔레그램 채널을 한 번에 서버사이드 검색으로
조회하고, 첨부된 PDF 리포트 본문과 수출입 그래프 이미지를 읽는 스킬.

**소스 수집 도구이지 판단 도구가 아니다** — 투자 조언 금지·출처 라벨 등 작업실의
절대 규칙은 이 스킬 안에서도 그대로 적용된다.

## 함께 들어있는 파일

```
server/server.py         텔레그램을 실제로 검색하는 MCP 서버 (단독 실행판)
server/login.py          최초 1회 텔레그램 로그인
server/requirements.txt  필요한 파이썬 패키지 5개
```

`server.py`는 **다른 레포에 의존하지 않는다** — 설정·세션 경로를 자기 파일 위치 기준으로
잡으므로 이 폴더를 어디에 두든 동작한다.

## 설치 (30분, 대부분은 클로드에게 시키면 된다)

1. **패키지 설치** — `server/` 폴더에 파이썬 가상환경을 만들고
   `pip install -r requirements.txt`. 클로드에게 "이 스킬의 server 폴더에 .venv 만들고
   requirements.txt 설치해줘"라고 하면 된다.
2. **텔레그램 API 키** — https://my.telegram.org → API development tools에서
   `TELEGRAM_API_ID` / `TELEGRAM_API_HASH`를 발급받아 `server/.env`에 넣는다.
   **이 파일은 절대 커밋하지 않는다**(비밀번호와 같다).
3. **로그인 1회** — `server/` 폴더에서 `python login.py`를 **직접** 실행한다
   (전화번호 → 인증코드 → 2FA). 대화형 입력이 필요하므로 AI가 대신 실행하지 않는다.
   봇이 아니라 **본인 계정 세션**이어야 한다 — 봇은 가입 이후 메시지만 보고 과거
   히스토리를 검색하지 못한다. `telegram_session.session`이 생기며, 이건 **내 텔레그램에
   들어갈 수 있는 열쇠**이므로 공유·커밋 금지. 기기마다 따로 로그인해야 한다.
4. **채널 가입** — `DOC_POOL`, `bornlupin`, `benineb9`, `BeOn_BeClear`에 본인 계정이
   가입돼 있어야 한다. 가입 안 된 채널은 `channel_errors`로 빠지고 나머지 결과는 정상.
5. **워크스페이스에 서버 등록** — 본인 워크스페이스 루트에 `.mcp.json`을 만든다.
   경로는 **본인 PC 경로로 바꿔야** 한다:

   ```json
   {
     "mcpServers": {
       "telegram-search": {
         "command": "C:\\경로\\peer-telegram-search\\server\\.venv\\Scripts\\python.exe",
         "args": ["C:\\경로\\peer-telegram-search\\server\\server.py"]
       }
     }
   }
   ```

   `.mcp.json`은 **PR에 포함되지 않는다** — 절대경로가 사람마다 다르고, 레포 루트
   `.mcp.json`은 여는 사람 모두에게 "이 프로그램을 실행할까요?"를 묻는 신뢰 결정이라
   남에게 밀어넣을 것이 아니기 때문이다(워크스페이스 `.gitignore`도 이미 막고 있다).
   **크레덴셜은 `server/.env`에만 있고 레포로 넘어오지 않는다.**

세션을 재시작하면 신뢰 여부를 한 번 묻고, 이후 `mcp__telegram-search__search_channel` /
`get_document_text` / `get_message_image`가 도구 목록에 잡힌다. `/mcp`로 확인할 수 있다.

그림으로 된 설치 안내: https://telegram-search-guide.vercel.app

세션 미인증 에러(`텔레그램 세션이 없음`)가 나면 위 3번 로그인부터 다시 해야 한다 —
대화형 입력이 필요하므로 AI가 대신 실행하지 않는다.

도구 이름은 `.mcp.json`에 등록한 서버 이름을 따른다. 위 예시대로면
`mcp__telegram-search__search_channel` 형태이고, 아래 절차에서는 서버 접두어를 빼고
`search_channel` / `get_document_text` / `get_message_image`로 적는다 — 세션에 실제
등록된 이름으로 호출한다.

## 절차

1. `search_channel(query, limit=15, auto_fetch_documents=8)`을 호출한다(`channel`은
   생략). `query`는 종목명/티커 등 키워드. 채널을 생략하면 기본 채널 목록
   (`DOC_POOL`, `bornlupin`, `benineb9`, `BeOn_BeClear`)을 전부 동시 검색해 최신순으로
   병합한 결과를 준다 — 서버사이드 검색이라 채널이 몇 개든, 히스토리가 길든 빠르다.
   특정 채널 하나만 봐야 할 때만 `channel="DOC_POOL"`처럼 지정한다(예: 수출입 데이터만
   필요하면 `channel="BeOn_BeClear"`).
2. 결과는 `{channels_searched, channel_errors, matches}` 형태다.
   - `channels_searched`: 실제로 검색을 시도한 채널 목록
   - `channel_errors`: 가입하지 않았거나 존재하지 않는 채널이 있으면 `{채널명: 에러}`로
     담긴다 — 전체 검색이 실패하지 않고 나머지 채널 결과는 정상적으로 들어온다. 있으면
     "이 채널은 계정이 가입돼 있지 않아 검색 못함"이라고 **반드시 알린다**(커버리지 공백을
     숨기면 "자료 없음"과 구분되지 않는다).
   - `matches`: 최신순 병합 목록. 각 매치는 `channel` 필드로 출처 채널을 표시한다.
3. `matches`의 최소 `auto_fetch_documents`(기본 8)건은 첨부 PDF 본문이 `document.text`에
   이미 들어있다(최대 16,000자) — 추가 호출 없이 바로 읽는다.
4. 각 매치는 캡션에서 파싱한 `parsed` 필드
   (`title`/`author`/`broker`/`opinion`/`target_price`)도 함께 온다.
5. 뒤쪽 매치(`has_document: true`인데 `document` 필드가 없는 것)의 본문이 필요하면
   `get_document_text(channel, message_id)`로 개별 조회한다 — `channel`은 그 매치 자신의
   `channel` 값을 쓴다(매치마다 소속 채널이 다를 수 있다).
6. **채널마다 게시물 형태가 다르다.**
   (아래는 2026-08-06에 채널별 최근 25건을 직접 표본 조사해 확인한 것이다.)
   - `DOC_POOL`(표시명 "소중한추억."): 라벨된 캡션 + PDF 첨부(증권사 리포트). 표본
     25건 중 7건이 PDF. 나머지는 **리포트 미리보기 이미지**로, `text`가 비어 있고
     `has_document: false`로 온다 — 읽을 내용이 없으므로 건너뛴다.
   - `bornlupin`(표시명 "루팡"): **외부 링크 채널이 아니다.** 뉴스·공시·해외 IB
     코멘트를 한국어로 정리한 **본문 글**이 그대로 `text`에 들어온다(예: "폭스콘
     2026년 7월 매출 … MoM +15.18%", SK하이닉스 해명공시 전문). 표본 25건 중 PDF 0건,
     링크 0건. 추가 fetch 없이 `text`를 읽으면 되지만 **2차 요약**이므로 단독 근거로
     쓰지 않고 공시·리포트 원문으로 확인한다.
   - `benineb9`(표시명 "비나인의 블로그 스크랩"): **여기가 외부 링크 채널이다.**
     제목도 설명도 없이 네이버 블로그 URL 한 줄만 `text`에 있다 —
     `has_document: false`, `parsed: {}`. 이 도구는 링크를 열지 않으므로 필요하면
     `WebFetch(text)`로 직접 열어 확인한다 — **URL만 보고 내용을 안다고 가정하지
     않는다.** 개인 블로그이므로 신뢰도를 가장 낮게 둔다.
   - `BeOn_BeClear`(표시명 "BeOn - 비온"): **수출입 데이터 채널.** 게시물은
     **그래프 이미지 + 캡션** 한 쌍이다. 캡션에는 **품목, 관련종목, 기간,
     잠정/확정 여부**만 있고 **금액·증감률 수치는 그래프 이미지 안에 있다.**
     수치가 필요하면 `get_message_image(channel, message_id)`로 이미지를 불러와
     **직접 보고 읽는다**(아래 6-1 참조). "관련종목" 태그는 품목-종목 연결 근거로
     인용하고, **"잠정치"인지 "확정치"인지 반드시 구분**해서 옮긴다(월 중순 잠정치는
     월말·익월에 갱신된다).

6-1. **이미지 안의 수치를 읽어야 할 때** — 매치의 `has_image`가 true면
   `get_message_image(channel, message_id, index=0)`를 호출한다. 이미지가 그대로
   돌아오므로 직접 보고 값을 읽는다. 한 게시물에 여러 장이면 `index`를 올려가며 본다
   (BeOn은 보통 0=월별 추이, 1=분기별 추이).
   - 그래프에서 읽은 수치는 **눈으로 읽은 값**이므로 정확한 값이 아니라 **눈금 기준
     근사치**임을 밝히고, 축 단위(달러/원)와 기간 라벨을 함께 옮긴다.
   - 범례에 "확정치"와 "10일/20일/말일"(잠정) 막대가 함께 있으므로, 어느 막대를
     읽은 것인지 명시한다.
   - **읽을 수 없을 만큼 흐리면 읽지 않는다** — 추측해서 숫자를 만들지 말고
     `unknown`으로 남기고 관세청/K-stat 확인을 권한다.
7. `matches`가 0건이면 검색한 채널 전체에 커버리지가 없다는 뜻 — 파라미터를 바꿔가며
   재시도하지 말고 그대로 보고한다. **"자료 없음"을 "특이사항 없음"으로 바꿔 쓰지 않는다.**

## 결과 정리 원칙

- 같은 종목에 여러 리포트가 걸리면 나열하지 말고 **증권사 | 발간일 | 투자의견 | 목표주가**
  비교표를 만든다. 이 표는 **증권사들이 무엇을 말하고 있는지의 기록**이지 작업실의 판단이
  아니다 — 표 위에 "각 증권사의 의견이며 추천이 아님"을 명시하고, 목표주가를 되풀이해
  권유하지 않는다.
- `parsed`(캡션 정규식 추출)는 위 네 항목까지만 커버한다. 매출액/영업이익/OPM/PER 같은
  추정치는 캡션에 없고 `document.text`(PDF 원문)의 추정 실적표에만 있으므로, 원문을 직접
  읽어 **증권사 | 발간일 | <연도>E 매출 | <연도>E 영업이익 | OPM | PER** 비교표를 별도로
  만든다. 이 표가 추정치의 수렴/분산을 보여주는 핵심이니 생략하지 않는다(브로커마다
  포맷이 달라 자동 파싱이 아니라 읽고 직접 추출해야 한다).
- 공통 언급 수치가 리포트 간에 일치하는지 짚어 교차 확인 근거로 삼고, 단일 리포트에서만
  나온 수치(피어 비교, DCF 가정 등)는 별도로 표시해 구분한다.
- `document.text`가 `truncated: true`면 앞부분만 읽은 것이다 — 리스크 요인·상세 분기표가
  필요하면 `get_document_text`를 더 큰 `max_chars`로 재호출한다.
- 산출물에서 **주장 / 근거 / 추정 / unknown**을 분리한다. 원문에서 확인 못 한 값은 채우지
  말고 `unknown`으로 적고 확인 방법을 제안한다.

## 출처 라벨

모든 수치·핵심 주장에 라벨을 붙인다. 이 스킬이 가져오는 것들의 기본 라벨:

| 소스 | 라벨 | 비고 |
|---|---|---|
| 리포트 PDF 원문의 확정 실적·공시 인용 | `[2차]` | 증권사가 1차 자료를 가공한 것 |
| 리포트의 추정 실적·목표주가·투자의견 | `[추정]` | 애널리스트 전망치 |
| 채널 게시물 캡션/`text` 요약 | `[2차]` | 단독 근거로 쓰지 않음 |
| 외부 블로그 링크(WebFetch) | `[2차]`, 신뢰도 낮음 | 개인 블로그일 수 있음 |
| `BeOn_BeClear` 캡션(품목·관련종목·기간) | `[2차]` | 관세청 HS코드 기반 비공식 가공 |
| `BeOn_BeClear` 그래프에서 눈으로 읽은 수치 | `[2차]`, 근사치 | 눈금 기준 판독값 — 정확한 값이 아님을 함께 표기 |
| DART 공시·관세청/K-stat 원자료 | `[1차]` | 재확인의 기준점 |

## 신뢰도 원칙

- 채널 게시물 본문(`text`, 캡션)은 **2차 가공된 요약**이므로 단독 근거로 쓰지 않는다.
  첨부된 `document.text`(리포트 원문)를 우선 인용한다.
- 외부 블로그 링크는 개인 블로그·비전문 매체일 수 있어 증권사 리포트나 DART 공시보다
  낮은 신뢰도로 취급한다 — 수치·날짜 주장의 단독 근거로 쓰지 않는다.
- `BeOn_BeClear`는 게시물 스스로 특정 HS코드에 "수출 데이터 신뢰할 수 없음" 같은 경고를
  다는 경우가 있다 — 그런 문구가 있으면 그 항목은 인용하지 않는다. 금액이 중요한 판단
  근거일 때는 관세청/무역협회 K-stat 등 `[1차]` 출처로 재확인을 권한다.
- 리포트 한 건이 곧 교차 확인 완료가 아니다 — 다른 증권사 리포트나 DART 공시 등 독립된
  출처로 한 번 더 확인한 뒤 수치·날짜 주장을 제시한다.
- 인용 형식: "출처: <증권사명> <애널리스트명> 리포트 <제목>(<발행일>), 텔레그램 <채널명>
  게시" — 여러 채널을 동시 검색했으므로 무조건 DOC_POOL이라고 쓰지 않고 매치의 `channel`
  값을 쓴다.
- 검색 결과가 소유자의 결론을 대신하지 않는다. 결론을 요구받으면 먼저 질문의 선명도와
  소스 계획을 점검하게 한다.

# macro-brief — 거시 브리핑 (시황 모드 / 브리핑 모드)

## 이 스킬은

- **어떤 병목**: "기록이 안 남는다 — 특히 **판단의 이유**가 안 남는다"
- **입력 → 남는 것**: 거시 발표 하나 + 소유자의 판단 → `macro/brief/`에 "내 의견 / 시장 대세 / 갈린 지점 / 왜 그렇게 봤는지"가 출처 라벨과 함께 남는다
- **설치 후 첫 실행**: `시장 브리핑 해줘` (초보자용 시황부터). 발표 당일이면 `브리핑 열자`
- **아직 안 되는 것**: 애널리스트 서베이 컨센서스 정밀값은 무료 API에 없어 `[추정]`까지만. CME FedWatch 원본도 유료 → 언론 인용본(`[2차]`)

## 두 모드 — 먼저 어느 쪽인지 정한다

| | **시황 모드 (open)** | **브리핑 모드 (blind)** |
|---|---|---|
| 부르는 말 | "시장 브리핑 해줘", "지금 시장 어때", "다음 발표 언제야" | "브리핑 열자", "시장 컨센서스는 어때", 발표일 hook |
| 시장 의견 | **바로 보여준다** | 소유자 답 **전엔 한 글자도 안 보여준다** |
| 소유자 의견 | 요구하지 않는다 | **필수** — 이게 이 모드의 전부 |
| 남는 것 | 없음 (읽고 끝) | `macro/brief/YYYY-MM-DD-{지표}.md` |
| 상세 절차 | `references/mode-b-market.md` | `references/mode-a-blind.md` |

### 모드 결정 규칙

1. 부르는 말이 위 표 어느 쪽인지로 판단한다.
2. **오늘/어제가 발표일인데 시황 모드를 부르면 → 거절하고 브리핑 모드를 권한다.**
   > "오늘 {지표} 발표일입니다. 시황을 먼저 보시면 blind가 깨져서, 소유자 판단이 시장 의견의 복사본이 됩니다. 브리핑으로 여시겠습니까?"
   소유자가 그래도 시황을 원하면 따른다 — 단 그 지표는 이번 회차 blind를 포기한 것으로 기록한다.
3. 애매하면 묻는다. 섞지 않는다.

**시황 모드는 브리핑 모드의 예습이다.** 시황 끝에 다음 발표일을 붙여, 그날 브리핑으로 오게 만든다.

## 경계 — 이 스킬 고유 함정만 (클럽 절대 규칙은 `CLAUDE.md`가 있으면 그쪽)

| 안 하는 것 | 이유 |
|---|---|
| 브리핑 모드에서 소유자보다 **먼저** 시장 의견 노출 | 앵커링. 이 모드의 생명 = blind 순서 |
| 컨센서스·논평을 사실처럼 단정 | 전부 `[추정]`(발표 전 예상) / `[2차]`(논평·여론). "대세는 이렇게 본다"까지만 |
| 매수·매도·목표가·기대수익률·"이렇게 하세요" | 컨센서스 **전달**과 조언은 다르다 |
| **시황 모드에서 "그래서 뭘 사요?"에 답하기** | 범용 시황일수록 이 압력이 세다. 답은 하나: "그 판단은 소유자가 합니다. 저는 시장이 뭐라 하는지까지만 옮깁니다" |

## 산출물

| 모드 | 경로 |
|---|---|
| 브리핑 | `macro/brief/YYYY-MM-DD-{지표}.md` — 예: `2026-07-29-FOMC.md` (hook이 이 경로로 중복 알림을 막는다) |
| 시황 | 파일 없음. 화면 출력만 |

템플릿은 각 모드의 `references/` 파일에 있다.

## 지표 현황은 다시 긁지 않는다

`macro-track` 스킬이 이미 매일 1차 출처로 지표를 확인해 **`macro/dashboard.md`**에 쌓는다.
시황 모드는 그 파일을 **읽어서** 쓴다. 같은 지표를 두 스킬이 각각 긁으면 숫자가 갈린다.

- `macro/dashboard.md`가 없거나 오래됐으면 그 사실을 알리고, `macro-track`을 먼저 돌리자고 제안한다.
- 대시보드에 없는 것만 그 자리에서 1차 출처로 확인한다.

## 자기 점검 (마무리 전 필수)

- [ ] (브리핑 모드) 소유자 답 **전에** 컨센서스를 노출하지 않았나 — 이 모드의 생명
- [ ] 모든 컨센서스·의견에 `[추정]`/`[2차]` 라벨이 붙었나
- [ ] 매수·매도·목표가·기대수익률·"하세요"가 **한 글자도** 없나
- [ ] 못 구한 값을 지어내지 않고 `unknown` + 확인 링크로 뒀나
- [ ] 발표일·지표 수치를 **지어내지 않았나** (일정은 `config.md`, 수치는 1차 출처 또는 대시보드)
- [ ] 소유자 파일(`CLAUDE.md`·`context.md`·`journey.md`)을 안 건드렸나 — 승격은 소유자만
- [ ] 커밋에 `.env`·`*.key`가 안 섞였나

## 마무리

브리핑 모드로 끝냈으면, 드러난 판단을 세 줄 결산으로 침전시킬지 소유자에게 묻는다
(기준→`CLAUDE.md`, 판단→`context.md`, 보강→`journey.md` — 파일이 있는 경우만. `session-wrap` 스킬이 있으면 그쪽에 넘긴다).
**승격은 소유자만 한다.**

## 설치 (남에게 넘길 때)

1. `.claude/skills/macro-brief/` 폴더 전체를 복사한다 (`SKILL.md`, `config.md`, `references/`, `hooks/`).
2. 자동 알림을 쓰려면 `.claude/settings.json`에 SessionStart hook을 등록한다:
   ```json
   { "hooks": { "SessionStart": [ { "hooks": [ { "type": "command",
     "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/skills/macro-brief/hooks/session-start.sh\"" } ] } ] } }
   ```
   hook 없이도 스킬은 동작한다 — 발표일을 알아서 알려주지 않을 뿐이다.
3. `config.md`의 발표 일정이 올해 것인지 확인한다. 지난 연도면 1차 출처(Fed·BLS·BEA 캘린더)로 갱신한다.
4. API 키는 선택이다. 없어도 WebSearch 폴백으로 동작한다 (`config.md`의 API 상태 표 참고).
5. 첫 실행: `시장 브리핑 해줘`

## 이 스킬은
- 어떤 병목: 매일 PE/VC 뉴스 직접 찾아 읽는 게 번거로웠어
- 입력 → 남는 것: "pe-vc-daily" 요청 → vault에 날짜별 브리핑 노트(오늘자 관련 기사 요약 + 출처라벨 + 회사/펀드 위키링크)
- 설치 후 첫 실행: "pe-vc-daily"
- 아직 안 되는 것: 아직 모름

# pe-vc-daily — 국내 PE/VC 데일리 브리핑

vault 경로: **이 스킬을 처음 쓰는 사람은 자신의 Obsidian vault 절대경로를 여기에 적어 넣는다** (deal-note를 이미 쓰고 있다면 그 vault와 동일 경로를 쓴다 — 같은 회사·펀드가 딜 노트와 데일리 노트 양쪽에 나오면 위키링크로 자동 연결된다). vault 경로를 모르면 참가자에게 먼저 물어본다.

첫 실행 예시: "pe-vc-daily" 또는 "오늘 PE/VC 뉴스 정리해줘" → vault 경로 확인 → 오늘자 브리핑 생성

**고정 매체와 목록 URL** (WebSearch로 찾지 말고 아래 URL을 직접 WebFetch한다 — 검색은 날짜순 정렬을 보장하지 않아서 "오늘 뉴스"가 아니라 최근 몇 달 치가 섞여 나온다):

| 매체 | 목록 URL | 비고 |
|---|---|---|
| 벤처스퀘어 | `https://www.venturesquare.net/category/news-contents/news-trends/news` | 일반 스타트업 뉴스 목록 — "투자유치" 태그 페이지는 실제로 투자 기사가 거의 안 걸러져(2026-07-30 확인, 4건 전부 무관) 폐기. 이 목록도 인베스트조선·더벨처럼 관련성으로 걸러야 함 |
| 딜사이트 | `https://dealsite.co.kr/issue/1670` | "PE 투자 포트폴리오" 큐레이션 목록 — 매일 갱신되는 게 아니라 오늘자가 없을 수도 있음. 카테고리 페이지(`/categories/075023` 등)는 JS 렌더링이라 WebFetch로 못 읽어서 대안 없음(2026-07-30 확인) |
| 인베스트조선 | `https://www.investchosun.com/svc/news/list.html?catid=2` | PE/VC 전용 카테고리가 없어 전체 뉴스가 섞여 나옴 — 아래에서 관련성으로 걸러야 함 |
| 더벨 | `https://www.thebell.co.kr/front/free/contents/news/article.asp?svccode=01&page=1` | svccode 파라미터가 실제로는 카테고리를 안 걸러줘서 전체기사가 나옴 — 인베스트조선과 마찬가지로 아래에서 걸러야 함 |

## 절차

1. 위 4개 URL을 각각 WebFetch해서 오늘자(또는 참가자가 지정한 날짜) 기사 제목·날짜 목록을 가져온다. 딜사이트는 목록 자체가 PE/VC 큐레이션이라 그대로 쓰면 되고, 나머지 셋(벤처스퀘어·인베스트조선·더벨)은 일반 뉴스가 섞여 있으므로 그중 PE/VC 딜(투자·인수·펀드레이징·엑싯 등) 관련성이 있는 것만 추린다. 목록에 오늘 날짜 기사가 없으면(딜사이트처럼 매일 갱신 안 되는 경우) 그 사실을 밝히고 넘어간다 — 억지로 지난 기사를 오늘 것처럼 쓰지 않는다.
2. 그중 딜 관련성이 높은 순으로 최대 10건을 고르고, 고른 기사마다 원문 URL을 WebFetch로 다시 읽어 본문을 확인한다. **10건을 채우기 위해 관련성 낮은 기사를 억지로 끼워 넣지 않는다** — 오늘 나온 게 10건이 안 되면 나온 만큼만 쓰고, 몇 건인지·왜 부족했는지(예: 특정 매체 접속 실패) 브리핑 앞에 적는다. 유료 기사라 본문 전체를 못 읽으면 헤드라인·리드 문단만으로 판단하고, 본문을 다 못 읽었다는 사실을 해당 항목에 남긴다.
3. 각 항목마다 다음을 뽑는다:
   - 제목과 원문 링크
   - 매체명 + 출처 라벨: 회사·펀드의 공식 발표를 그대로 전한 기사는 `[1차]`, 다른 매체 보도의 재인용·해설이면 `[2차]`, 기사에 명시되지 않았지만 문맥상 추론한 내용이면 `[추정]`
   - 한 줄 요약 — 원문에 나온 수치·사실만 쓰고 지어내지 않는다. 확인이 안 되는 값은 빈칸 대신 `unknown`으로 적는다.
   - 등장하는 회사·펀드·자문사는 `[[이름]]` 위키링크로 표시한다. vault에 해당 이름의 노트가 아직 없으면 deal-note와 같은 방식으로 빈 스텁 노트를 만든다 — 이렇게 해야 같은 당사자가 나중에 다른 딜/브리핑에도 나올 때 백링크로 이력이 쌓인다.
4. vault에 날짜별 노트로 저장한다. 파일명: `YYYY-MM-DD PE-VC 데일리.md`

   ```yaml
   ---
   tags: [daily-brief, PE, VC]
   date: YYYY-MM-DD
   sources: [더벨, 인베스트조선, 딜사이트, 벤처스퀘어]
   count: 실제로 담은 건수
   ---
   ```

   본문은 담은 항목을 번호 순서대로 나열한다 (제목 → 라벨 → 요약 → 위키링크 → 원문 링크).
5. 저장된 파일 경로와, 이번에 새로 생긴 스텁 노트 목록을 참가자에게 알려준다.
6. **웹페이지 생성**: vault 루트에서 파일명이 `* PE-VC 데일리.md` 패턴인 파일을 전부 찾아 날짜순(최신이 위)으로 정렬한다.
   - 가장 최근 날짜는 "오늘의 브리핑" 섹션에 카드 그리드로 펼쳐서 보여준다. 각 항목은 카드 하나: 라벨 배지 → 제목(원문 링크) → 회사/펀드명 칩(위키링크 대체, 하이퍼링크 없이 pill 텍스트로만) → 매체·날짜·확인 상태 메타 → `<details><summary>요약 보기</summary><p>...</p></details>`(기본 접힘) → "원문 보기" 버튼. 카드 왼쪽 테두리 색은 라벨([1차]=초록 계열, [2차]=파랑 계열, [추정]=보라 계열)에 맞춘다.
   - 헤더에는 그라디언트 배경의 히어로 영역을 두고, 스킬 소개 한 줄 + 통계 pill(오늘 날짜, 총 건수, 매체별 건수, 라벨 분포)을 보여준다.
   - 나머지 날짜들은 "아카이브" 섹션에 `<details class="archive-day"><summary>날짜 (건수)</summary>...</details>` 형태로 접어서 나열한다(최신순). 펼쳤을 때 안쪽도 "오늘의 브리핑"과 동일한 카드 그리드 구조를 재사용한다.
   - 지난 날짜가 하나도 없으면 "아직 지난 날짜가 없습니다 — 내일부터 여기에 쌓입니다"라고 표시한다.
   - 특정 날짜 파일의 frontmatter나 항목 형식을 읽을 수 없으면, 그 날짜는 "형식을 읽지 못해 건너뜀"이라고 표시하고 나머지는 정상 처리한다(전체가 죽지 않게 한다).
   - 위키링크(`[[이름]]`)는 칩(`<span class="chip">이름</span>`)으로만 표시한다(하이퍼링크·그래프 기능 없음).
   - 정확한 마크업·CSS(색상 변수, `.card`/`.chip`/`.stat-pill`/`.summary-toggle`/`.archive-day` 등 클래스 정의)는 vault 루트의 기존 `index.html`이 있으면 그 스타일을 그대로 재사용한다 — 새로 디자인하지 않는다. 없으면(첫 실행) `docs/superpowers/plans/2026-07-30-pe-vc-daily-webpage.md`의 v2 확정본 구조를 참고해 만든다.
   - vault 루트에 `index.html`로 저장한다(기존 파일 있으면 덮어쓴다). 저장된 경로를 참가자에게 알려준다.

## 하지 않는 것

- 투자 조언(매수·매도 추천, 목표가, 기대수익률)을 생성하지 않는다 — 기록·요약만 한다.
- 근거 없는 수치를 만들지 않는다. 확인 불가하면 `unknown`.
- 고정 매체 4곳 외에 다른 곳에서 기사를 가져오지 않는다 — 매체를 넓히고 싶으면 참가자가 먼저 이 스킬을 수정해야 한다.

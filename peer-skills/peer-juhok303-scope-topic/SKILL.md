## 이 스킬은
- 어떤 병목: 어떤 주제에 대해 리서치할 때, 주제를 같이 이해하고 앞으로 리서치하면서 집중해야 하는 질문거리들을 미리 계획하지 않은 채 자료부터 모으는 문제
- 입력 → 남는 것: 리서치할 주제를 입력하면 그 주제를 이해하면서 정리한 `<topic>-scope.md`가 생성됨. 그 뒤 질문거리들을 정리한 `<topic>-questions.md`가 생성됨
- 설치 후 첫 실행: `scope-topic <주제>` 로 호출
- 아직 안 되는 것: 향후 어떤 프레임워크로 리서치 주제들을 더 효율적으로 접근할지는 계속 정리해나가야 함

# Scope Topic — 리서치 대상 범위 잡기

리서치를 시작하기 전, 대상(트렌드/산업/기업 중 하나)의 경계와 접근 프레임워크를 사용자와 합의하고 기록한다. 이 단계 없이 바로 자료부터 모으면 방향 없이 쌓이기만 한다.

**독립 실행 스킬** — 이 워크스페이스 밖 다른 스킬이나 서브에이전트에 의존하지 않는다. 배경 조사가 필요한 구간은 Claude가 WebSearch로 직접 찾아 초안을 제시하고, 사용자 확인을 받는다.

## 산출물

`<topic>-scope.md` + `<topic>-questions.md` (`<topic>`은 kebab-case 토픽명). 저장 위치는 항상 **현재 Claude 세션이 켜져 있는 작업 디렉터리**(cwd) — 따로 묻지 않는다. 토픽명을 파일명에 접두사로 넣는 이유: cwd에 하위 폴더 없이 바로 저장하므로, 한 폴더에서 여러 토픽을 다루면 `scope.md`끼리 서로 덮어써버리기 때문.

## 절차

### 0. 대상 확인
- 토픽명(kebab-case)부터 확인한다.
- 현재 디렉터리에 이미 `<topic>-scope.md`가 있으면 읽어서 뭐가 채워져 있고 뭐가 비어 있는지 확인 → 빈 부분부터 이어서 진행.
- 없으면 새로 만든다: 카테고리를 확인한다.
  - **트렌드**: 산업 전반에 영향을 주는 구조적 동인. 상위 토픽 없음.
  - **산업**: 특정 제품 + 밸류체인 단계. 유의미한(단순 언급이 아닌 실질적) 영향을 주는 트렌드가 있으면 기록(선택, 여러 개 가능).
  - **기업**: 특정 회사. 속한 산업을 반드시 기록(필수, 여러 개 가능).
  - 상위 토픽은 실제로 존재/합의된 것만 적는다 — 이 스킬이 상위 토픽을 대신 만들지 않는다(아래 "하지 않는 것" 참고).
- 현재 디렉터리에 `<topic>-scope.md`를 만들고 "정의 / 핵심 개념 / 상위 토픽 / 범위 파라미터 / 프레임워크" 5개 섹션 제목만 뼈대로 써둔다.

### 1. 정의
- 토픽의 경계(무엇을 포함/제외하는지)와 핵심 개념·용어를 가볍게 조사한다(전수 수집이 아니라 꼭 필요한 몇 개만).
- 조사 결과를 평이한 말로 설명하고, 사용자의 명시적 확인/정정을 받는다. **합의 전에는 다음 단계로 넘어가지 않는다.**
- 확정된 경계 + 개념 정의를 `<topic>-scope.md`의 "정의" / "핵심 개념"에 기록.
- 수치·통계를 인용할 경우 출처 라벨을 붙인다: `[1차]`(공시·계약서·원데이터·직접 인터뷰), `[2차]`(언론·애널리스트 리포트·산업 통계), `[추정]`(회사 제시 전망·AI 추론·가정). 라벨을 붙일 수 없는 수치는 쓰지 않고 `unknown`으로 남긴다.

### 2. 범위 파라미터
- 조사 없이 사용자와 직접 협의: 지역, 밸류체인 구간/단계, 시계열(몇 년 범위).
- `<topic>-scope.md`의 "범위 파라미터"에 기록.

### 3. 프레임워크
- 고정된 기본값 없이, 이 토픽을 실제로 어떻게 뜯어볼지 사용자와 자유롭게 협의해서 요소를 정한다(예: 밸류체인, 경쟁 구도, 규제 환경, 공정 맵, 가치 배분 등 — 토픽 성격에 맞는 것만 고른다).
- 확정된 요소와 우선순위를 `<topic>-scope.md`의 "프레임워크"에 기록.

### 4. 질문
- 위에서 합의된 프레임워크 요소별로 리서치 질문 목록 초안을 작성한다(새 조사 없이, 지금까지 합의된 내용에서 도출).
- `<topic>-questions.md`로 저장(scope 파일과 같은 폴더). 사용자에게 보여주고 조정받는다.
- 1회성 목록이 아니라 리서치가 진행되며 계속 갱신되는 백로그로 취급한다.

### 5. 마무리
- 스코핑이 끝났음을 알리고, 다음은 이 질문들을 하나씩 조사(수집)하는 단계라고 안내한다.

## 부분 재진입

리서치 도중 정의되지 않은 개념이 갑자기 튀어나오면 전체 절차를 다시 돌 필요 없다 — **1. 정의**만 그 용어에 대해 실행하고 `<topic>-scope.md`의 "핵심 개념"에 추가한 뒤, 원래 하던 작업으로 돌아간다.

## 하지 않는 것

- 상위 토픽(트렌드/산업)을 대신 만들지 않는다 — 없으면 사용자에게 먼저 만들라고 안내만 한다.
- 실제 자료 수집·추출·리포트 작성은 이 스킬의 범위가 아니다 — 범위와 질문 초안까지만.
- 근거 없는 시장 규모·점유율·성장률을 만들지 않는다 — 확인 안 되면 `unknown`으로 남기고 확인 방법을 제안한다.
- 투자 조언(매수·매도, 목표가, 기대수익률)을 하지 않는다.

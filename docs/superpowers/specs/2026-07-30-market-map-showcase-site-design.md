# market-map 소개 사이트 — 설계

- 날짜: 2026-07-30
- 대상 스킬: `.claude/skills/market-map/SKILL.md`
- 목적: 클럽 동료들이 이 페이지 하나로 market-map 스킬을 이해하고, 실제 결과물을 보고 "나도 써볼까" 판단할 수 있게 한다.

## 배경

market-map은 모의투자 고정 유니버스(26개 ETF, 5개 자산군)를 대상으로 (1) 각 종목이 뭘 추종하는지 정리하고 (2) 이후엔 "오늘 왜 움직였는지" 이슈를 자산군 단위로 계속 쌓는 참가자 소유 스킬이다. 실제 산출물은 `outputs/market-notes/overview.md`/`overview.html`에 이미 쌓여 있고, 코스피 사이드카 발동(2026-07-29)처럼 소개용으로 쓸 만한 실사례가 들어있다.

## 저장소 / 배포 구조

- **새 별도 public 저장소**를 만든다. 이 workspace(`my-investor-club-workspace`)에는 `context.md`, `journey.md`, `club/` 등 개인 판단 기록이 섞여 있어 그대로 공개하면 안 된다.
- 사이트 코드만 담은 새 repo → GitHub push → **Vercel 배포**(정적 사이트, 빌드 스텝 없음).
- **주의**: 새 GitHub repo 생성, GitHub push, Vercel 배포는 되돌리기 까다롭거나 외부에 노출되는 행동이다. 구현 단계에서 실제로 실행하기 직전에 사용자에게 한 번 더 확인받는다.

## 기술 스택

- 빌드 도구 없는 순수 정적 `index.html` 한 장 (+ 인라인 또는 단일 CSS).
- Vercel은 정적 파일을 그대로 서빙 — 프레임워크 불필요.
- 라이트/다크 모드 모두 지원 (기존 `outputs/market-notes/overview.html`의 CSS 변수 패턴 재사용 가능).
- 반응형: 모바일 폭에서도 표/카드가 깨지지 않게.

## 콘텐츠 (확정)

### 1. Hook
> "모의투자를 하고 있는데, 26개 종목을 한 번에 보고 싶다면?"
> 국내주식·해외주식·채권·원자재·리츠 — 5개 자산군, 26개 ETF를 한 장으로.

### 2. 병목 (1인칭 톤, 짧은 문단)
> "26종목을 ticker-review로 하나하나 공부했는데, 정작 어느 시장을 골라야 할지는 보이지 않았다. 흩어진 걸 한 번에 모아볼 데가 없었다."

### 3. 핵심 기능 3가지 (benefit 중심 bullet)
1. 이번주 시장에서 있었던 주요 이슈를 자산군별로 정리해준다 (기사·뉴스 기반, 출처 라벨 포함)
2. 26종목이 각각 뭘 추종하는지, 패시브/액티브·환헤지 여부까지 표로 한눈에
3. 자산군 전체가 움직인 건지 개별 종목만의 이슈인지, 다른 자산군과 반대로 움직였는지까지 구분

### 4. 데모 — 실제 이슈 로그 2건을 나란히
`outputs/market-notes/overview.md`에서 그대로 가져온 실제 항목 (라벨 포함, 정적 스냅샷):

- **2026-07-29** "코스피·코스닥 동반 급락, 양대 시장 매도 사이드카 발동" — 코스피 -5.98%(5663.24), 7월 한 달 -28.9%(1990년 이후 최대 월간 낙폭) `[2차]`
- **2026-07-29** "급락 배경: 반도체 피크아웃 우려 + 레버리지 반대매매 악순환" — 삼성전자·SK하이닉스 레버리지 ETF 반대매매 규모 직전 41거래일 대비 약 77% 증가, "담보가치 하락→강제매도→추가 하락" 악순환 지적 `[2차]`

두 항목을 "무슨 일이 있었나" / "왜 그랬나" 쌍으로 배치. 하단에 "이 데이터는 예시 시점 스냅샷" 명시 + 전체 결과물(`overview.html`) 링크.

**제외**: 자산군 개요 표(원자재/채권 등) 발췌는 넣지 않는다 — 병목·기능 프레이밍이 "이슈 정리"로 재조정되면서 불필요해짐.

### 5. 쓰는 법 + 설치
- `/market-map` 한 줄 설명: 처음이면 26종목 개요, 이후엔 이슈만 누적.
- SKILL.md 받는 법 (GitHub raw 링크 또는 repo 링크).

### 6. 원칙 (신뢰 장치, 3줄 이내)
- 모든 수치·핵심 주장에 `[1차]`/`[2차]`/`[추정]` 라벨, 확인 안 되면 `unknown`.
- 매수·매도 추천, 목표가, 기대수익률, **배분 비율**을 생성하지 않는다.
- **제외 확정**: "26종목 중 2종목 코드 불일치를 스스로 잡아냈다" 사례는 아직 미해결 내부 이슈([[project_ticker_code_mismatch]] 참고)라 공개 페이지에 넣지 않는다.

## 데이터 흐름

전부 정적 스냅샷 — 실시간 연동 없음. 데모의 이슈 로그 2건은 설계 시점에 `overview.md`에서 수동으로 발췌해 HTML에 하드코딩한다. 나중에 갱신하고 싶으면 최신 이슈로 수동 교체.

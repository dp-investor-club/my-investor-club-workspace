# pe-vc-daily — 동료가 잘 쓸 수 있게 (더벨 링크 복구 + 첫 실행 안내)

## 문제

`pe-vc-daily`는 이미 `peer-skills/peer-junha-pe-vc-daily/`에 올라가 있어 동료가 `/update`로 받아갈 수 있는 상태다. 그런데 오늘(2026-08-05) 데일리 브리핑을 두 번 시도하는 동안 더벨(모바일)이 두 번 다 원문 링크(href) 추출에 실패했다 — 이건 `peer-skills/README.md`가 말하는 "설명이 안 맞아 안 켜지는" 종류의 실패가 아니라, 이미 원인을 아는 순수 기술적 파싱 버그다. 이런 건 동료가 또 발견하게 두는 게 의미 있는 피드백이 아니라 그냥 시간 낭비다. 또한 "이 스킬은" 4줄이 club 컨벤션상 유일한 설치 안내인데, 실행 시간·결과 건수 편차에 대한 기대치가 없어 처음 받는 동료가 "적게 나오면 실패한 건가?" 헷갈릴 수 있다.

## 결정

1. 더벨 링크 추출 버그를 실제로 고친다 (기술 수정).
2. 그 수정이 curl/Bash를 못 쓰는 동료 환경에서도 조용히 죽지 않고 기존 동작으로 fallback 되게 만든다 (환경 적응).
3. SKILL.md "이 스킬은" 4줄만 갱신한다 — 새 섹션은 만들지 않는다 (club 컨벤션 유지).
4. `.claude/skills/pe-vc-daily/`와 `peer-skills/peer-junha-pe-vc-daily/` 두 사본을 동일하게 유지한다.

병합 기능 개발(직전 스펙, `2026-08-05-pe-vc-daily-dedup-design.md`)과 달리 이번은 새 기능이 아니라 **기존 기능을 동료 환경에서도 신뢰 가능하게 만드는** 작업이다.

## 더벨 링크 복구 — 원인과 3단계 절차

**원인**: 더벨 모바일 뉴스 목록(`https://m.thebell.co.kr/m/news.asp?svccode=01`)은 기사 링크를 `<a href>`가 아니라 JS `onclick=readNews('newskey')`로 그린다. 실제 이동 로직은 페이지 소스에 `location.href="newsview.asp?svccode=01&newskey="+newskey+...`로 박혀 있고, 원본 HTML 안에 `attr={"newskey":"...","subject":"...","freedtm":"...",...}` 형태로 기사 데이터가 인라인 JS 변수로 그대로 들어있다. WebFetch는 HTML→마크다운 변환 과정에서 이 인라인 JS 데이터(및 onclick의 href 없는 링크)를 버리기 때문에 지금까지 항상 실패했다.

SKILL.md 절차 1단계(핵심 매체 WebFetch)에서 더벨 항목만 다음 3단계로 교체한다:

1. **1차 (Bash/curl)**: 목록 URL을 curl로 가져와 `attr={"newskey":"...", ...}` 패턴에서 newskey·제목·게시일을 추출하고, `https://m.thebell.co.kr/m/newsview.asp?svccode=01&newskey=<값>`으로 기사 URL을 재구성한다. 이후 기존 2단계(본문 확인)에 합류 — 재구성한 URL을 WebFetch로 읽는다.
2. **2차 (curl 실패 시)**: Bash를 못 쓰거나 네트워크가 막히면 기존처럼 WebFetch로 목록 페이지를 읽어 제목·날짜만이라도 확보한다.
3. **최종 폴백**: 1·2차 모두 링크를 못 구하면 지금처럼 더벨을 제외하되, **어느 단계에서 왜 실패했는지**(예: "curl 명령을 찾을 수 없음" / "newskey 패턴 없음 — 사이트 구조 변경 추정") 브리핑 상단에 구체적으로 남긴다. "안 됐다"만 적지 않는다 — 동료가 자기 환경 문제인지 사이트 변경 문제인지 구분할 수 있어야 한다.

더벨 사이트 구조가 나중에 다시 바뀌어도(예: newskey 패턴 변경) 이 절차는 "실패 시 사유를 남기고 폴백"하므로 브리핑 자체가 깨지지는 않는다.

## SKILL.md "이 스킬은" 4줄 갱신

club 컨벤션(`peer-skills/README.md`: "이 4줄이 설치 안내의 전부")을 지켜 새 섹션 없이 기존 4줄만 고친다.

- **어떤 병목**: 변경 없음.
- **입력 → 남는 것**: 변경 없음.
- **설치 후 첫 실행**: 기존 문장 유지 + "여러 매체를 순서대로 확인하느라 몇 분 걸릴 수 있고, 그날 나온 딜 뉴스 양에 따라 결과가 보통 4~10건으로 달라진다 — 적게 나온다고 실패한 게 아니다" 추가.
- **아직 안 되는 것**: 기존 병합 관련 문장 유지 + "더벨은 curl로 링크를 복구하지만 동료 환경에서 Bash/curl을 못 쓰면 여전히 빠질 수 있다(그 경우 이유가 브리핑에 남는다)" + "딜사이트는 매일 갱신되지 않아 오늘자가 없는 날이 많다" + "마켓인사이트는 PE/VC 전용 카테고리가 없어 관련성 낮은 기사가 섞일 수 있다" 추가.

# Lecture Notes Builder

강연·수업·특강을 들을 때마다 흩어지는 메모를 한 곳에 쌓아가는 skill. 목적은 "정리를 예쁘게"가 아니라 **나중에 이 폴더만 봐도 그 강연에서 누가 무슨 말을 했는지 다시 찾을 수 있는 것**이다. 그래서 요약으로 뭉개기보다 원문의 논리 구조를 살려서 정리한다.

(원본: `ai-layer/skills/lecture-notes-builder` — 여러 학생이 공유하는 `students/{GitHub ID}/lectures/` 구조였던 것을, 이 저장소는 단일 소유자 작업실이라 레포 루트의 `lectures/`로 이식했다.)

## 전제

- 오디오 파일(mp3/m4a/wav 등)은 로컬에 설치된 `whisper` CLI(OpenAI Whisper)로 전사한 뒤 진행한다. `which whisper`로 설치 여부를 먼저 확인한다 — 없으면 `brew install openai-whisper`로 설치할지 참가자에게 묻는다 (pytorch가 딸려 있어 용량이 크고 시간이 걸린다는 점을 알린다).

## 입력으로 받아야 하는 것

- 강연/수업 내용 원문 — 텍스트(메모/전사본)이거나 오디오 파일
- 메타데이터: 날짜, 강연/수업명, 발표자

메타데이터가 텍스트 안에 없으면 참가자에게 직접 묻는다. 날짜나 발표자를 텍스트에서 추측해 지어내지 않는다 — 모르면 `미상`으로 남기고 나중에 채우게 한다.

## 실행 흐름

### 0단계 — 오디오 전사 (오디오 파일이 입력일 때만)

```bash
whisper "{오디오 파일 경로}" --model small --language Korean \
  --output_format txt --output_dir "lectures/_raw"
```

- 첫 실행 시 모델 가중치를 내려받는다 (인터넷 필요, 수십~수백 MB). 이후로는 오프라인으로 동작한다.
- 모델 크기는 속도/정확도 트레이드오프다. 기본값은 `small`. 강연이 길거나(1시간+) 속도가 중요하면 `base`를, 발표자 발음이 어렵거나 전문용어가 많아 정확도가 중요하면 `medium`을 참가자에게 제안한다.
- 강연이 한국어가 아니면 `--language` 값을 맞게 바꾼다. 확실하지 않으면 옵션을 생략해 자동 감지하게 둔다.
- 전사 결과(raw txt)는 `lectures/_raw/`에 그대로 보존한다 — 2단계에서 다듬은 결과와 원본 ASR 결과를 구분해 나중에 대조할 수 있게 하기 위해서다.
- ASR은 완벽하지 않다. 알아듣기 힘들거나 명백히 잘못 인식된 구간은 임의로 지어내 채우지 않는다 — `[판독 불가]`로 표시하고 결과 보고 때 참가자에게 확인을 요청한다.

### 1단계 — 메타데이터 확정

원문에서 날짜/강연명/발표자를 찾아본다. 명확하지 않으면 참가자에게 짧게 확인 질문한다. (예: "오늘 날짜로 저장할까요? 발표자 성함은 어떻게 표기할까요?")

### 2단계 — 구조화된 원문 정리

원문을 다음 기준으로 정리한다.

- **주제/흐름 단위로 소제목을 나눈다.** 강연이 실제로 흘러간 순서를 따른다 — 내용을 재배치해서 "더 논리적으로" 보이게 만들지 않는다.
- **발표자의 표현을 최대한 살린다.** 핵심 주장, 비유, 숫자, 예시는 발표자가 쓴 표현 그대로에 가깝게 남긴다. 매끄러운 문어체로 다시 쓰면 그 순간 원문에서 멀어진다.
- **군더더기만 걷어낸다.** "어...", "그러니까", 말 끊김, 중복된 되풀이는 정리하되, 내용이나 뉘앙스는 지우지 않는다.
- **요약으로 대체하지 않는다.** "AI 트렌드에 대해 설명함" 같은 한 줄 요약이 아니라, 무엇을 어떤 근거로 왜 그렇게 말했는지가 남아야 다음에 다시 참고할 수 있다.
- 강연 중 나온 수치나 주장 중 출처가 불분명한 것은 원문 그대로 옮기되 그것이 발표자의 주장/추정이라는 점이 문맥에서 드러나게 쓴다 (예: "발표자는 ~라고 언급했다"). 이 skill이 사실관계를 검증하거나 투자 판단 근거로 승격시키지 않는다 — 그건 참가자가 별도로 할 일이다.

### 3단계 — 파일 저장

`lectures/YYYY-MM-DD-{강연명-slug}.md` 로 저장한다. 폴더가 없으면 만든다.

파일 템플릿:

```markdown
---
날짜: {YYYY-MM-DD 또는 미상}
강연/수업명: {제목}
발표자: {이름 또는 미상}
입력 형태: {실시간 메모 / 녹음 전사}
---

# {제목}

## {소제목 1}

{정리된 내용}

## {소제목 2}

{정리된 내용}
```

### 4단계 — 인덱스 갱신

`lectures/index.md`가 없으면 아래 헤더로 새로 만든다. 있으면 새 행을 날짜순으로 추가한다 (기존 행은 건드리지 않는다).

```markdown
# 강연 노트 인덱스

| 날짜 | 강연/수업명 | 발표자 | 한 줄 요약 | 파일 |
|---|---|---|---|---|
| {YYYY-MM-DD} | {제목} | {발표자} | {한 줄 요약} | [{파일명}](./{파일명}) |
```

한 줄 요약은 인덱스에서만 쓴다 — 개별 강연 파일 안에는 요약이 아니라 구조화된 원문을 남긴다는 원칙과 구분한다.

### 5단계 — 결과 보고

무엇을 만들었는지 짧게 보고한다.

```text
저장 완료 — lectures/{파일명}
인덱스 갱신 — {제목} 1행 추가 (총 {n}건)
확인이 필요한 부분: {미상으로 남긴 메타데이터, [판독 불가] 표시 구간, 또는 없음}
```

## 금지

- 강연에 없던 내용을 추가하거나 발표자의 발언 취지를 바꾸지 않는다. ASR 오인식 구간을 그럴듯하게 추측해 채우는 것도 포함된다.
- 강연 속 수치·전망을 검증된 사실이나 투자 판단 근거로 자동 승격하지 않는다 — CLAUDE.md의 출처 표기 원칙은 이 skill의 산출물에도 적용된다.
- `lectures/` 밖에는 아무것도 쓰지 않는다.

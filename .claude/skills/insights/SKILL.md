# Insights

강연이 끝날 때마다 돌리는 짧은 기록 스킬. 참가자가 두 번째로 지은 스킬. Notion MCP가 연결되어 있으면 자동으로, 아니면 되물어서 기록한다.

## 태그 체계 (2026-07-23 확정)

내용을 아래 6개 태그 중 해당하는 것으로 분류한다. 하나의 항목에 여러 태그가 붙을 수 있다(불릿 단위로 태그).

- `#시장데이터` — AUM·시장 규모·상품·기관 정보 등 사실 데이터
- `#투자전략` — 투자 판단 기준, 프레임워크, 딜소싱·회수 방법론
- `#커리어` — 진입 경로, 채용 기준, 이직·전환 사례
- `#태도` — 마인드셋, 습관, 조언성 내용
- `#실무스킬` — AI·툴 활용법, 업무 자동화·정리 방법론
- `#거시환경` — 거시경제, 지정학, 산업 구조 변화

구분이 애매하면 참가자에게 되묻는다 — 임의로 정하지 않는다. 새 카테고리가 필요해 보이면 추가하기 전에 참가자에게 먼저 제안한다.

## 절차 (Notion 자동 동기화 — 우선)

Notion MCP 도구(`notion-search`, `notion-fetch`, `notion-query-data-sources`, `notion-update-page`)가 사용 가능하면 이 경로를 먼저 시도한다.

1. `notion-search`로 "Insight Database"를 찾아 `notion-fetch`로 스키마를 확인한다(data source URL 확보).
2. `insights.md`를 읽고, 기존 줄에 숨겨진 `<!-- notion:{url} -->` 주석들을 모아 "이미 동기화된 Notion 페이지 URL 목록"을 만든다.
3. `notion-query-data-sources`(SQL 모드)로 Insight Database를 조회하되 **`Select = 'DREAMPLUS'`인 행만** 대상으로 한다(커피챗·HerVest·콜드메일 등 강연 외 기록은 제외).
4. 조회된 행 중 URL이 2번의 동기화 목록에 없는 행만 "새 행"으로 취급한다.
5. 새 행마다 `notion-fetch`로 **페이지 본문 전체**(Keynote·Key Takeaway 등)를 읽는다 — `Keywords` 속성 값만으로는 정보가 부족하다. `People` relation도 `notion-fetch`로 열어 이름(및 소속·직업이 있으면 함께)을 확인한다.
6. 본문에서 실제로 다뤄진 핵심 내용을 뽑아 위 태그 체계 중 해당하는 태그별로 묶는다. 내용을 새로 짓지 않는다 — 본문에 있는 것만 압축·요약한다. **서술형 문장이 아니라 단어·짧은 구 중심으로 축약한다** — 조사·서술어를 최대한 걷어내고 명사구를 쉼표로 나열한다(예: "Time over Timing, 위기 시 우량자산 매수, 현금 여력 확보" — "~이며 ~해야 한다" 같은 문장형 금지).
7. `insights.md` 맨 아래에 새 행마다 아래 형식으로 추가한다. **같은 태그에 해당하는 내용은 한 줄로 묶는다** (불릿을 태그마다 반복하지 않는다) — 세션 안에서 태그별로 한눈에 훑어볼 수 있게 하는 것이 목적이다(2026-07-26 피드백 반영):

```
- {Date} / {People 이름}({소속·직업, 있으면}) — {페이지 제목} <!-- notion:{Notion 페이지 URL} -->
  - **#태그A**: {내용 1} / {내용 2}
  - **#태그B**: {내용 3}
```

8. 정리한 태그별 불릿 전체를 하나의 텍스트로 합쳐 `notion-update-page`로 해당 페이지의 `Keywords` 속성에 덮어쓴다(줄바꿈으로 불릿 구분). raw 원문은 Notion에도 더는 남지 않는다 — 참가자가 2026-07-23 세션에서 확정한 결정. 업데이트 실패 시 알리고 `insights.md` 기록은 그대로 유지한다.
9. 새 행이 없으면 "Notion에 새로 추가된 강연 기록이 없습니다"라고 안내하고 아래 "절차 (수동)"으로 넘어갈지 참가자에게 묻는다.
10. 추가/업데이트한 줄들을 참가자에게 그대로 보여준다.

## 절차 (수동 — Notion 연동이 없거나 참가자가 직접 입력을 원할 때)

1. 참가자에게 자연어로 되묻는다:
   - 오늘 강연의 연사는 누구였나요?
   - 오늘 새롭게 알게 된 것을 한 줄 이상 적어주세요 (여러 개면 여러 줄). 강연 중 노션에 바로 적은 raw 메모를 그대로 붙여넣어도 된다.
2. 참가자가 답하면 참가자의 말 그대로 받아 적는다 — 대필하거나 요약을 새로 지어내지 않는다. raw 메모가 이어 붙어 있으면 문장 단위로만 나눈다(내용 추가·축약 금지).
3. 각 내용을 위 태그 체계 중 해당하는 태그로 묶는다. 구분이 애매하면 참가자에게 되묻는다 — 임의로 정하지 않는다.
4. `insights.md` 맨 아래에 아래 형식으로 한 줄(또는 여러 줄) 추가한다. 같은 태그는 한 줄로 묶는다:

```
- {YYYY-MM-DD} / {연사}
  - **#태그A**: {인사이트 1} / {인사이트 2}
  - **#태그B**: {인사이트 3}
```

5. 수동 절차는 Notion 페이지가 없으므로 Notion 업데이트는 하지 않는다 — `insights.md` 기록만 남긴다.
6. 저장 후 방금 추가된 줄을 그대로 보여준다.

## 규칙

- 연사나 인사이트를 참가자가 말하지 않은 내용(수동) 또는 Notion 페이지 본문에 없는 내용(자동)으로 지어내지 않는다.
- Notion 자동 동기화는 `Select = 'DREAMPLUS'` 범위만 다룬다 — 커피챗·HerVest·콜드메일 기록은 이 스킬의 대상이 아니다.
- 종목 추천·목표가 등 투자 조언으로 이어지는 인사이트는 그대로 기록하되(사실 기록), AI가 판단을 덧붙이지 않는다.
- insights.md는 기본적으로 append만 한다 — 참가자가 명시적으로 전체 재정리를 요청한 경우(2026-07-23처럼)에만 기존 줄을 고친다.
- `<!-- notion:{url} -->` 주석은 중복 동기화 방지용이므로 지우지 않는다.
- Notion 자동 동기화 경로에서는 정리된 태그 불릿 전체로 Notion의 `Keywords` 속성을 덮어쓴다 — raw 원문은 Notion에도 보존되지 않는다(2026-07-23 참가자 결정).

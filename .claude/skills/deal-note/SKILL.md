# deal-note — 딜 뉴스를 Obsidian 노트로

vault 경로: `C:\Users\junha\OneDrive\바탕 화면\IB\PE`

1. 참가자가 URL이나 키워드를 준다. 키워드만 오면 어떤 기사/URL을 볼지 먼저 확인한다.
2. WebFetch로 원문을 읽는다.
3. 아래 항목을 추출한다 — 원문에 명시된 수치·주장에는 `[1차]`, 다른 보도의 재인용이면 `[2차]`, 원문에 없지만 유추한 것이면 `[추정]` 라벨을 붙인다. 확인 불가한 항목은 값 대신 `unknown`으로 적는다.
   - 매수자 / 매도자
   - 거래 대상
   - 거래 금액·구조
   - 자문사
   - 날짜
4. vault 폴더에 마크다운 파일로 저장한다. 파일명: `YYYY-MM-DD 딜당사자 요약.md`. **Obsidian에서 그래프·Dataview로 엮이도록** 아래 형식을 따른다:

   - **YAML frontmatter** (속성) — Dataview/필터링용. `unknown`인 필드도 값 그대로 적는다(비우지 않는다):
     ```yaml
     ---
     tags: [deal, IB]
     buyer: "[[매수자명]]"
     seller: "[[매도자명]]"
     target: 거래 대상
     amount_krw: 금액(라벨 포함)
     advisor: "[[자문사명]]"
     date: YYYY-MM-DD
     status: unknown 또는 확인된 상태
     source: 원문 URL
     ---
     ```
   - **본문 첫 줄**: `[[매수자명]]`이 `[[매도자명]]`의 `[[거래 대상]]`을 인수 — 이렇게 위키링크로 당사자를 걸어서 Obsidian 그래프뷰에 노드가 생기게 한다.
   - 위 항목 표 (라벨 포함)
   - "추정/미확인" 섹션 — 기사에 없거나 불확실한 부분을 따로 모아 적고, 확인 방법을 제안한다.
   - 매수자/매도자/자문사마다 각각 `[[이름]]` 노트가 vault에 없으면 빈 스텁으로 하나씩 만들어, 나중에 같은 당사자가 다른 딜에도 나오면 백링크로 전체 이력이 모이게 한다.
5. 저장된 파일 경로와, 새로 생긴 위키링크 스텁 목록을 참가자에게 알려준다.

투자 조언(매수·매도 추천, 목표가, 기대수익률)은 이 스킬에서도 생성하지 않는다 — 기록·구조화만 한다.

# 주식리서치 리포트 자동 작성 (4-에이전트 오케스트레이션)

종목명/티커 하나를 받아 **정해진 양식**(증권사형 10섹션)에 맞춰 리서치 리포트를 완성하고
옵시디안 볼트에 저장한다. 이 스킬은 **오케스트레이터**다 — 직접 자료를 다 읽지 않고,
4개 서브에이전트에 일을 나눠준 뒤 결과를 저장한다.

## 아키텍처 (왜 이렇게 나눴나)
- 자료 1종 = 에이전트 1개 전담 → 거대한 사업보고서/10-K 토큰이 메인 대화로 안 올라옴(토큰 절약).
- **1·2·3번 병렬**(자료 분담), **4번만 취합** → 병목은 마지막 조립 하나.
- **국내/미국은 절차 파일이 따로 있다.** 이 SKILL.md는 시장 감지와 공통 원칙만 담고,
  에이전트 구성·경로·단계별 절차 같은 상세 내용은 시장별 파일에만 있다.
  **감지된 시장의 절차 파일 하나만 읽는다** — 관련 없는 시장 절차까지 매번 읽는 건 순수 낭비다.
- 데이터 소스 규칙·해설형 작성 원칙 등은 각 서브에이전트 파일과 `양식.md`/`양식_US.md`에
  이미 있다. 여기서 반복하지 않는다 — 반복은 스킬이 커질수록 매 실행 고정비만 늘릴 뿐이다.

```
/주식리서치 <종목명|티커>
   └ [시장 감지]
       ├ 국내 → `국장-절차.md` Read → 그 절차대로 진행
       └ 미국 → `미장-절차.md` Read → 그 절차대로 진행
           (1·2·3번 병렬 → stock-editor(공용) → 스킬이 저장)
```

## 0) 시장 감지 (가장 먼저)
- 인자로 종목명/티커를 받는다. **없으면 물어본다.**
- **미국**: 영문 대문자 1~5자 티커(NVDA·AAPL·KO), 또는 알려진 미국 상장사의 한글명(엔비디아·애플·테슬라·마이크로소프트 등).
- **국내**: 한글 종목명, 6자리 숫자 종목코드.
- 애매하면 **자료 루트에서 종목 폴더를 찾아 보정한다**(어느 쪽에 있는지가 곧 시장이다):
  `C:\Users\송범석\Desktop\송범석\주식리서치\` 아래 `국내\<섹터>\<종목명>\` vs `미국\<섹터>\<종목명>\`
  → `Get-ChildItem -Recurse -Directory`로 탐색.
- 그래도 애매하면(예: 동명이인 종목) **사용자에게 물어본다**.

## 절차
시장이 정해지면 **해당하는 파일 하나만 Read**하고 그 지시를 그대로 따른다:
- 국내 → `C:\Users\송범석\.claude\skills\주식리서치\국장-절차.md`
- 미국 → `C:\Users\송범석\.claude\skills\주식리서치\미장-절차.md`

각 절차 파일에는 에이전트 구성·경로·1~5단계(종목 확인 → 병렬 호출 → 편집 취합 → 저장 → 마무리 보고)가
그 시장에 한해서만 적혀 있다.

## 공용 원칙 (오케스트레이터 자신이 지킬 것)
- **저장은 오케스트레이터가 직접 한다.** 4번(`stock-editor`)이 반환한 완성 리포트에서 `[검수 메모]`는
  떼어내 파일에는 포함하지 않되, 사용자에게는 요약해 전달한다.
- **자료 결핍을 조용히 넘어가지 않는다** — 부족한 자료·확인 필요 수치는 마무리 보고에서 먼저 말한다.
- 양식(출력 구조)을 바꾸면 각 서브에이전트 담당 지침도 함께 손본다.

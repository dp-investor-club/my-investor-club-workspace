# Week 4 — 내 것을 남이 쓸 수 있게

Week 3에서 내 병목을 AI로 처음 풀었다. 그건 **1번 사용자(나)** 까지였다.

오늘의 프레임: **내가 만든 것을 나 없이 남이 쓸 수 있나?** 지금까지 여러분은 계속 받는 쪽이었다 — `/update`로 클럽 스킬을 받고, 재료를 받았다. 오늘 처음 **주는 쪽**이 된다.

**유일한 성공 기준: PR 하나를 올린다.** 스킬이 완벽할 필요는 없다. 남이 받을 수 있는 자리에 놓이면 성공이다.

---

## STOP PROTOCOL

각 블록은 2턴으로 진행한다.
```
Phase A: 설명 + "지금 해보세요" 안내 → ⛔ STOP (퀴즈·되묻기 금지)
   ⬇ 참가자가 "완료/다음"
Phase B: 확인/짧은 점검 → 다음 블록 이동 여부 확인
```
Phase A 끝에는 반드시:
```
---
👆 위 내용을 직접 해보세요. 끝나면 "완료" 또는 "다음"이라고 입력해 주세요.
```
그 뒤엔 어떤 도구 호출·텍스트도 출력하지 않는다.

## 진행 규칙

- 한 번에 한 블록. Block 1(점검) → Block 2(연결) → **Block 3(PR, floor)** → Block 4(결산).
- **Block 3의 PR 1건이 오늘의 완주선이다.** 시간이 부족하면 Block 2를 줄여서라도 Block 3에 도달한다.
- git/환경에서 막히면 그 자리에서 해결한다 — 에러를 그대로 붙여넣게 해서 같이 푼다. 명령을 외우게 하지 않는다.
- 참가자 파일(journey.md/CLAUDE.md/context.md)은 참가자 말을 받아 적는다. 대필 금지.
- 종목추천·목표가는 오늘도 금지어다.

---

## Block 1 — 내 스킬 점검 (`/skill-tuneup`)

**`/skill-tuneup`을 호출**한다. 없으면 `/update` 먼저.

그 스킬이 3문항 진단(발동/산출/이양)을 하고 걸린 것 하나를 그 자리에서 고친다. 오늘 PR로 보낼 스킬이 여기서 정해진다.

점검할 스킬이 하나도 없는 경우: Week 3에서 만든 것이 없다는 뜻이다. 이때는 만들기부터 한다 — journey.md의 병목 한 문장을 스펙으로 SKILL.md 하나를 짓고(20분 상한), 바로 Block 3으로 간다. Block 2는 건너뛴다.

## Block 2 — 연결 경로 넓히기

Claude Code에 밖을 붙이는 길은 여러 갈래다. 오늘은 **하나만 실제로 연결한다.**

| 갈래 | 무엇 | 방향 |
|---|---|---|
| **스킬** | 지침을 준다 (내가 쓴 절차) | 안 |
| **MCP** | 접근을 준다 (공시·뉴스·노션 등 외부 소스) | 받는 쪽 |
| **플러그인** | 스킬·명령 묶음을 한 번에 설치 | 받는 쪽 |
| **CLI** | 터미널 도구를 AI가 대신 실행 | 양쪽 |

진행:
1. Week 2에서 `journey.md`에 적어둔 **"다음에 연결할 MCP 후보"** 를 먼저 찾아본다. 있으면 그것부터 — 2주 전 본인이 고른 것이다.
2. 없으면 진행자가 소개한 플러그인 중 하나를 고른다.
3. 하나만 설치하고 **한 번 실행해서 실제로 붙었는지 본다.** 설치만 하고 넘어가지 않는다.
4. 붙은 뒤 한 줄로 정리하게 한다: **"이건 내가 밖으로 나가는 길인가, 밖이 나한테 들어오는 길인가?"** — 이 구분이 오늘 배우는 것이다.

막히면 15분에서 끊고 Block 3으로 간다. 연결은 오늘의 완주선이 아니다.

## Block 3 — 브랜치 + PR (floor)

`/submit`을 호출한다. 브랜치 생성 → 커밋 → push → PR 생성까지 `/submit`이 순서를 보장한다. 참가자가 git 명령을 칠 필요는 없다.

호출 전에 확인 두 가지:
1. **GitHub 계정 이름을 강사에게 전달했는지** — collaborator 초대가 되어 있어야 push가 된다. 안 되어 있으면 그 자리에서 진행자에게 알린다.
2. **SKILL.md에 "이 스킬은" 4줄이 있는지** — 없으면 `/skill-tuneup` Step 4로 먼저 채운다. 이게 남이 읽을 유일한 안내다.

PR이 올라가면 링크를 `journey.md`에 날짜와 함께 append 한다:
`- (2026-07-30) 내 스킬 PR: <링크>`

`Permission denied` / push 거부가 나면 `/github-helper`로 전환한다.

## Block 4 — 세 줄 결산 + 제출

**`/session-wrap`을 호출**해 세 줄 결산을 남긴다(기준→CLAUDE.md / 판단→context.md / 보강→journey.md).

결산이 끝나면 Slack 제출 문구를 만들어 복사하게 한다:
```
[Week4 제출]
- 내 스킬 PR: (링크)
- 점검에서 걸린 것 / 고친 것: (한 줄)
- 오늘 연결한 것: (플러그인/MCP 이름 + 받는 쪽인지 주는 쪽인지)
- 아직 안 풀린 부분: (한 줄)
```
수업에서 안내된 제출 채널에 **자리에서 바로** 올리면 완료.

예고 한 줄: "다음 주엔 남들이 만든 하네스가 왜 그 자리를 잡았는지 봅니다 — 그리고 여러분 것을 캠프로 들고 갑니다."

# Research: 대상 하나를 조사해 남기는 문서

## 이 스킬은

- 어떤 병목: 강연장에 들어갈 때 그 업계의 말과 구조가 미리 안 깔려 있는 막막함, 그리고 조사해도 판단이 안 남아 다음번에 처음부터 다시 시작하는 것 (2026-07-23, 2026-07-30)
- 입력 → 남는 것: 대상 이름 하나와 모드. 공시·시세·클럽 자료를 1차 재료로 받아, 출처 라벨이 붙은 md 한 건과 읽기용 html 한 건.
- 설치 후 첫 실행: `조사해줘, 셀바스AI 판단 모드로`
- 아직 안 되는 것: 해외 공시(SEC 등)는 안 받는다. 비상장 재무는 보도 인용만 되고 `[2차]`다. PDF에서 표를 구조로 못 뽑고 텍스트만 뽑는다.

> 2026-07-30 Week 4에서 `prebrief`, `memo`, `research-prep` 세 스킬을 하나로 합친 것이다.
> 셋은 재료 모으는 순서와 라벨 규칙, 산출 형식이 같았고 마지막 절만 갈렸다.

## 모드 (먼저 정한다)

대상을 받으면 어느 모드인지 먼저 확인한다. 참가자가 말하지 않으면 묻는다.

| 모드 | 언제 | 마지막에 남는 것 | 산출 위치 |
|---|---|---|---|
| **강연** | 강연이나 멘토링 전 | 그 자리에서 물어볼 가설형 질문 3개 | `weeks/week-0N/` |
| **판단** | 회사 하나를 기록할 때 | 무엇이 확인되면 판단이 바뀌는지 | `outputs/` + `context.md` 초안 |
| **스캔** | 새 대상을 얕게 볼 때 | 돈의 흐름 3문장과 소스 목록 | `outputs/` |

- 강연 모드는 산업을 앞에 크게 둔다. 연사가 속한 회사 하나로 좁히지 않는다.
- 판단 모드는 회사 하나만 받는다. 상장사와 비상장 둘 다 된다.
- 스캔 모드는 종목, 산업, VC, 펀드, 특정 질문을 다 받는다. 30분 안에 끝나는 분량이다.
- 같은 대상에 여러 모드를 돌려도 된다. 앞서 만든 문서가 있으면 읽고 시작하되, 산업 서술을 복사하지 않고 링크로 가리킨다.

## 컨설팅 리서치와 정리 노트가 갈리는 네 지점

이 스킬은 이 넷을 문서 구조로 강제한다.

1. **두괄식**: 사실 기반 top-line을 맨 위에 놓는다. (0절)
2. **삼각검증**: 핵심 수치는 두 개의 독립 출처나 두 개의 계산 방법으로 교차한다. (1절, 8절)
3. **프레임 적용**: 밸류체인에 이익 풀을 얹고, 경쟁사를 같은 축으로 비교한다. (1절, 5절)
4. **증거 추적성**: 핵심 주장마다 출처 수와 신뢰도 등급을 붙인다. (8절)

## 어투

작업실 전역 규칙을 따른다. 별도로 복사해 두지 않는다.

- 문체 규칙 원본은 `CLAUDE.md`의 "응답 규칙"이다. 줄표 금지, 비유와 수사 금지, 훈수 문장 금지가 거기 있다.
- `scripts/style-guard.py`가 PreToolUse hook으로 걸려 있어 `outputs/`와 `weeks/`에 쓰는 md와 html을 쓰기 직전에 검사한다. 걸리면 그 자리에서 고친다.
- 파일을 쓰기 전에 `humanizer-kr`을 돌린다. 표, 라벨, 출처 링크, 수치는 그대로 두고 문장만 손본다.

이 스킬에만 해당하는 것 셋을 더 지킨다.

- **0절은 결론이 아니라 사실 진술이다.** 지금 이 대상에 무슨 일이 일어나고 있는지를 숫자로 적는다.
- **이익 풀, comps, 삼각검증은 구조를 드러내는 도구다.** 투자 판단 문장으로 넘기지 않는다.
- **배수는 계산 결과다.** 계산 근거를 표에 같이 적고, 싸다거나 비싸다는 판단은 쓰지 않는다.

### 1. 클럽 강의 자료 `[2차]`

레포 안 `club/week-0N/`에 있다. 주차별로 네 칸이다.

| 폴더 | 들어있는 것 |
|---|---|
| `lectures/` | 클럽이 만든 강연 요약 |
| `materials/` | 사전 공지, 설문 미러 |
| `sources/` | 개념 정리 노트 |
| `submissions/` | 각 조가 제출한 것 |

- `club/week-0N/README.md`를 먼저 읽는다. 그 주에 실제로 무엇이 있는지 표로 적혀 있다.
- 대상 연사 이름과 회사로 파일명을 훑는다.
- `club/`이 없거나 비어 있으면 `/update`를 실행해 받는다. 받은 뒤에도 없으면 클럽에 아직 없는 것이다.
- `club/`은 읽기전용이다. 고치지 않는다.
- 정리본은 제3자가 옮긴 문서이므로 라벨은 `[2차]`다. 본인이 그 자리에 있었어도 마찬가지다.
- 소속 표기가 파일마다 다를 수 있다. 같은 연사의 소속이 주차별 자료에 서로 다른 법인명으로 적혀 있는 경우가 있었다. 어긋나면 최신 날짜 파일을 우선하고 차이 자체를 문서에 적는다.

PDF가 섞여 있으면 텍스트를 뽑는다. 한글 파일명은 bash에서 인코딩이 깨지므로 파이썬으로 처리한다.

```bash

PYTHONUTF8=1 python -c "import fitz,glob;[print(fitz.open(p).load_page(0).get_text()) for p in glob.glob('club/**/*연사명*.pdf',recursive=True)]"
```

### 3. DART 전자공시 `[1차]` (판단 모드 필수)

인증키는 환경변수로만 받는다. 코드나 레포 파일에 적지 않는다.

```bash
python -m pip install pymupdf                # 처음 한 번만 (2번에서 이미 했으면 생략)
export DART_KEY=...                          # PowerShell: $env:DART_KEY="..."

python .claude/skills/research/scripts/dart.py find --stock 058970
python .claude/skills/research/scripts/dart.py acnt 00396925 2025 11011
python .claude/skills/research/scripts/dart.py owner 00396925 2025
python .claude/skills/research/scripts/dart.py list 00396925 20240101 20261231
python .claude/skills/research/scripts/dart.py doc 20260515001878 --save q1.txt
```

인증키는 `https://opendart.fss.or.kr`에서 무료로 발급된다.

훑는 순서는 이렇다.

- **정기보고서**: 최신 분기보고서와 직전 사업보고서. 매출 유형별 구성, 재무상태표, 특수관계자 거래 주석, 주식기준보상 주석이 여기 있다.
- **수시공시 목록**: `list`로 최근 2년을 훑고 아래를 먼저 연다.
  - `단일판매·공급계약체결` (정정 포함): 금액, 상대방, 기간, 대금지급 조건. 계약상대방과 회사의 관계가 적혀 있다.
  - `매출액또는손익구조30%이상변동`: 연간 실적을 감사 전에 확정 공시한 것. 회사가 밝힌 증감 사유가 붙어 있다.
  - `대표이사변경`, `주식등의대량보유상황보고서`, `주식매수선택권부여에관한신고`
- **정정본 확인**: 같은 보고서에 `[기재정정]`이 있으면 원본과 무엇이 다른지 본다. 계약 공시는 증액 정정이 흔하다.

배관에서 걸리는 것.

- `find`는 회사명 부분 일치로 여러 건을 돌려준다. corp_code를 눈으로 확인하고 다음 명령에 넣는다. 틀린 corp_code는 에러가 아니라 빈 결과로 온다.
- 재무 API가 분기를 "013 데이타 없음"으로 돌려줄 때가 있다. 그때도 분기보고서 원문에 손익과 재무상태표가 들어 있다. `doc --save`로 떨군 뒤 잘라 읽는다.
- 주요계정 API(`acnt`)는 당기순이익을 안 준다. 순손익은 분기보고서의 요약재무정보나 손익구조변동 공시에서 받는다.
- 특수관계자 거래 주석에는 전분기 수치가 나란히 실려 있다. 한 문서만으로 전년 동기 비교가 된다.
- 종속기업 지분율, 제품별 매출, 지배·비지배 순손익은 전부 분기보고서 원문에 있다.

### 5. 웹 검색 `[2차]`

1번부터 3번까지에서 확정한 정확한 사명으로만 검색한다. 사명이 흔들린 채로 검색하면 형제 회사 자료를 긁어온다.

한 각도로 한 번 검색하고 끝내지 않는다. 아래로 나눠 훑고 같은 사실이 두 출처에서 확인되는지 본다.

- 감독기관과 협회 통계 (시장 규모, top-down)
- 회사 IR, 공시, 홈페이지 (`[1차]`, 수익 구조와 수치)
- 분기별 실적 수치 (공시 사이 빈 분기를 메운다. 연간 합계가 공시와 맞는지 대조한다)
- 최근 6개월 사건 (계약, 인사, 지분 변동, 펀드 결성)
- 경쟁사와 comps (같은 밸류체인 칸의 다른 회사)
- 증권사 리포트 (사업 구조, 계약 내역, 시장 규모만. 목표주가와 투자의견은 옮기지 않는다)

## 산출 형식

| 모드 | 원본 md | 읽기용 html |
|---|---|---|
| 강연 | `weeks/week-0N/prebrief-<대상>.md` | `outputs/html/<YYYY-MM-DD>-prebrief-<대상>.html` |
| 판단 | `outputs/<YYYY-MM-DD>-memo-<대상>.md` | `outputs/html/<YYYY-MM-DD>-memo-<대상>.html` |
| 스캔 | `outputs/<YYYY-MM-DD>-<대상-slug>.md` | 만들지 않는다 |

주차 N은 `curriculum.md` 일정 표에서 그 날짜가 속한 주차로 정한다.

html을 만들면 아래를 이어서 한다.

1. 바로 열어서 소유자에게 보여준다.
2. `outputs/html/index.html` 목록에 새 줄을 추가한다.
3. `powershell -File scripts\sync-onedrive.ps1`을 돌려 문서 폴더로 사본을 내보낸다.

html은 파일 하나로 끝난다. 외부 CSS, 폰트, 스크립트를 부르지 않고 폰에서 읽을 수 있는 크기로 잡는다.

### 그림과 이미지

1. **우리가 다시 그리는 것을 먼저 한다.** 출처의 수치는 표로, 비중과 추이는 인라인 SVG로 직접 그린다. 색과 축은 `dataviz` 기준을 따른다. 이렇게 하면 출처 라벨을 붙일 수 있고 문서가 self-contained로 남는다.
2. **재현이 어려운 구조 다이어그램만 외부 이미지를 쓴다.** 밸류체인 도식, 지분 구조도가 여기 해당한다.
3. **외부 이미지는 핫링크하지 않는다.** 작은 것은 data URI로 박고, 큰 것만 `outputs/html/assets/`에 내려받아 상대경로로 링크한다. 후자면 문서가 assets 폴더에 의존한다는 것을 알린다.
4. 이미지마다 캡션에 출처와 링크, `[2차]` 라벨을 단다. 저작권이 불분명하면 이미지 대신 표로 옮긴다.

### 0. 지금 이 대상에 일어나고 있는 일

3~4문장. 전부 사실 진술이고 결론이 아니다. 각 문장에 출처 라벨. 숫자가 없으면 아직 조사가 덜 된 것이다.

강연 모드는 세 줄을 이렇게 잡는다.

1. **이 사업을 실제로 결정하는 동인 2~3개.** 매출이 아니라 이익이 어디서 나는지, 무엇이 바뀌면 이 사업이 흔들리는지.
2. **이익 풀에서 이 회사가 선 위치.** 밸류체인의 고마진 칸인지 저마진 칸인지, 그 자리가 구조적으로 방어되는지. 판단이 아니라 구조로 적는다.
3. **연사가 지금 안고 있는 긴장 하나.** 발언과 회사 방향이 어긋나는 지점, 제도 변화에 걸린 지점. 마지막 절 질문의 씨앗이 된다.

세 줄을 못 채우면 억지로 채우지 않고 `unknown`으로 두고 무엇을 더 봐야 하는지 적는다.

### 1. 산업 먼저 (삼각검증 규모 + 이익 풀)

회사보다 산업을 앞에 둔다. 소속 그룹과 형제 회사가 있으면 표로 구분한다. 이름이 비슷한 계열사를 혼동하는 것이 가장 흔한 실수다.

**시장 규모는 두 방법으로 교차한다.**

- 방법 1 (top-down): 감독기관과 협회 통계에서 전체 시장 규모.
- 방법 2 (bottom-up): 주요 사업자 합산, 또는 단가 곱하기 수량.
- 두 값이 크게 어긋나면 하나로 합치지 않는다. 둘 다 적고 차이의 이유를 한 줄, 못 대면 `unknown`.
- 가능하면 TAM, SAM, SOM으로 좁혀 적는다. 좁힐 근거가 없으면 전체 규모만.

**밸류체인 표에 이익 풀 열을 붙인다.** 밸류체인은 돈이 지나가는 순서로 적는다.

| 단계 | 하는 일 | 누가 마진을 가져가나 | 이 회사의 칸 |

- "누가 마진을 가져가나" 열에는 고마진인지 저마진인지와 그 구조적 이유(희소성, 규제 진입장벽, 전환비용, 규모의 경제)를 한 줄로. 수치 근거가 있으면 `[라벨]`, 구조에서 미룬 것이면 `[추정]`과 이유.
- 대상 회사가 선 칸을 표시하고, 무엇이 그 마진을 지키거나 위협하는지 사실로 적는다.

연혁이 필요하면 여기에 4~6줄로 붙인다. 사명 변경, 대주주 변경, 분사와 합병, 주력 사업 전환처럼 지금의 회사를 만든 사건만. 연도가 확인 안 되면 `unknown`.

### 2. 돈이 어디서 들어오는가

매출 유형별 표를 만든다.

| 매출 유형 | 성격 (반복되는가, 한 번으로 끝나는가) | 직전 연도 | 최근 분기 |

- **반복 매출과 일회성 매출을 반드시 가른다.** 구독과 유지보수는 반복, 프로젝트 구축과 일회성 라이선스는 아니다.
- 최근 분기를 4배 해 연환산하면 `[추정: 단순 연환산, 계절성 미반영]` 라벨을 붙인다.
- 회사가 말하는 사업 방향과 실제 매출 비중이 다르면 그 차이를 숫자로 적는다.
- 운용사면 관리보수와 성과보수의 요율과 기준(허들), 제조사면 단위당 매출과 원가 구조로 쪼갠다.

### 3. 이 대상 고유의 축

**절 이름을 대상마다 바꾼다.** 여기가 이 스킬에서 유일하게 열려 있는 자리다.

고르는 규칙은 매출이나 이익의 절반 이상을 좌우하는 요인 하나다.

| 축 | 언제 이걸 고르나 | 무엇을 표로 만드나 |
|---|---|---|
| 지배구조 | 최대 고객과 최대주주가 같은 집단일 때 | 지분 표 + 특수관계자 매출 표 |
| 연결 구조 | 매출 대부분이 자회사에서 나오거나, 과반 미만 지분을 실질지배력으로 연결할 때 | 종속기업 지분율 표 + 지배·비지배 순손익 표 + 연결 대 별도 실적 표 |
| 규제와 제도 | 매출이 인허가, 수가, 보조금에 걸려 있을 때 | 제도 변경 연표 + 해당 매출 규모 |
| 고객 집중도 | 상위 몇 곳이 매출 대부분일 때 | 고객별 매출 비중 + 계약 만기 |
| 원가 구조 | 원재료나 인건비가 이익을 결정할 때 | 원가 항목별 비중 + 판가 전가 여부 |
| 기술과 특허 | 특정 기술의 존속이 사업을 결정할 때 | 특허 만료 시점 + 대체 기술 |

축을 못 고르겠으면 2절 표를 다시 본다. 가장 큰 매출 줄이 무엇에 걸려 있는지가 답이다.

**연결 구조가 축일 때 확인할 것** (2026-07-30 셀바스AI 실행에서 추가):

- 지분율이 과반 미만인데 연결에 들어와 있는 자회사가 있는지. 공시 주석의 "지배력판단근거"를 그대로 옮긴다.
- 자본총계에서 비지배지분이 차지하는 비중.
- 당기순손익을 지배기업 몫과 비지배지분 몫으로 나눈 표. 연결 순이익이 흑자여도 지배기업 몫이 적자일 수 있다.
- 별도 재무제표의 매출과 영업이익. 연결과 방향이 다를 수 있다.
- 자회사가 상장사면 지분율에 시가총액을 곱해 지분 가치를 낸다. `[추정]`을 붙이고 할인과 할증은 반영하지 않는다.

### 4. 숫자

표 네 개를 고정으로 만든다. 전부 공시 `[1차]`.

1. **연간 실적**: 최근 4개 연도. 매출, 영업이익, 영업이익률, 당기순이익. 영업 외 손익이 순이익을 크게 흔들었으면 사유를 한 줄.
2. **분기 매출**: 최근 6개 분기. 2차 출처를 쓰면 연간 합계가 공시와 맞는지 대조하고 그 사실을 적는다.
3. **재무상태**: 최근 분기말. 자산 항목과 자산총계 대비 비중. 비중이 큰 항목이 사업과 무관하면 그대로 드러낸다. 현금성 자산 합계와 직전 분기 영업손익을 나란히 둔다.
4. **주식수와 희석**: 자본금을 액면가로 나눠 주식수를 낸다. 전환사채, 신주인수권, 주식매수선택권으로 늘어난 부분. 미행사 스톡옵션은 수량과 행사가격, 현재 주가 대비 배수까지.

### 5. 지금 가격이 담고 있는 것

상장사만 쓴다. 기준일, 종가, 주식수, 시가총액을 먼저 적고 표를 만든다. **계산 근거 열을 반드시 둔다.**

| 지표 | 값 | 계산 근거 |

- PSR, PER, EV 계열 중 이 회사에 말이 되는 것만. 적자면 PER을 쓰지 않는다.
- 현금이나 비영업자산이 크면 그것을 뺀 시총으로 한 번 더 계산하고 `[추정]`을 붙인다.
- **같은 칸의 상장사 표(comps)를 붙인다.** 맨 위에 선정 기준 한 줄. 축이 같아야 비교다. 종목마다 대상 회사와의 관계를 한 줄로 적고, 관계를 못 대면 넣지 않는다.
- 수치와 조회 기준일만 옮긴다. 등락에 이유를 붙이지 않는다.

비상장이면 이 절 대신 투자 유치 이력을 적는다. 라운드, 시점, 투자자, 공개된 밸류에이션. 보도에 있으면 옮기되 전부 `[2차]`이고, 없으면 `unknown`.

시세가 없는 회사가 comps로 필요하면 뉴스로 사건 타임라인을 만든다. 회사별로 시점과 사건을 표로 적고 출처 링크를 단다. 거래 구조(인수 금액, 지분율, 조달 방식, 참여자)가 보도에 있으면 그대로 옮긴다. 그 딜의 주체가 대상 회사인지 형제사인지 구분한다.

### 6. 이 업계 말

강연장에서 나올 용어 5~8개. 각 한 줄 정의. 일반 경제 용어는 넣지 않고, 모르면 그 자리에서 막히는 것만 고른다. 8개를 넘기지 않는다.

### 7. 최근 뉴스

최근 6개월 안의 것 2~3개. 헤드라인, 매체, 날짜, 링크만 옮긴다. 해석과 전망은 붙이지 않는다. 전부 `[2차]`. 걸리는 것이 없으면 없다고 적는다.

### 8. 소스 목록과 신뢰도 등급

**8-1. 소스 목록**

| 소스 | 라벨 | 확인한 것 | 믿기 어려운 점 |

"믿기 어려운 점" 열을 비워두지 않는다. 비울 만큼 확실하면 "없음"이라고 쓴다.

**8-2. 신뢰도 등급**

0절, 1절, 2절의 핵심 주장을 표로 모아 등급을 붙인다.

| 핵심 주장 | 출처 수 | 등급 | 비고 |

- 등급은 독립 출처 2개 이상이고 1차 포함이면 `상`, 2개 이상이나 전부 2차면 `중`, 단일 출처면 `하`.
- `하`인 주장은 그 사실을 밝힌다. 강연에서 확인할 것이면 강연 모드의 마지막 절 질문으로 올린다.

### 9. 확인하지 못한 것

`unknown`으로 남은 것을 한자리에 모은다. 각 항목에 확인 방법을 한 줄.

## 마지막 절 (모드별 출구)

### 강연 모드: 가설형 인터뷰 가이드 (질문 3개)

검색으로 안 나오고 그 사람만 답할 수 있는 것. 이 절이 강연 모드의 절반이다.

질문마다 세 줄.

- **질문**: 그 사람만 답할 수 있는 형태로.
- **가설**: 이 질문으로 확인하려는 것. 확인되면 무엇이 맞고, 뒤집히면 무엇이 달라지는지.
- **근거**: 0절부터 8절의 어느 지점에서 나왔는지. 특히 이익 풀의 방어 여부, 연혁의 전환점, 발언 속 모순.

"요즘 업계 전망은 어떤가요" 같은 것은 버린다. 검색으로 나오면 질문이 아니다.

강연이 끝난 뒤 다시 부르면 아래를 덧붙인다.

```
## 강연 후: 맞았던 것과 틀렸던 것
- 미리 조사한 것 중 실제로 나온 것:
- 예상하지 못했던 것:
- 질문 3개 중 실제로 물어본 것과 답:
- 가설이 확인됐나 뒤집혔나:
```

여기서 나온 1차 정보는 `context.md` 소스 이력으로 옮길 재료가 된다.

### 판단 모드: 무엇이 확인되면 판단이 바뀌는가

네 덩이를 적는다.

1. **핵심 질문 3~5개.** 각 질문에 왜 그것이 판단을 뒤집는지 한 줄. 확인 가능한 형태여야 한다. 언제 확인되는지(실적 발표일, 계약 만기)를 적을 수 있으면 적는다. "전망은 어떤가" 같은 것은 질문이 아니다.
2. **결정 규칙.** 이번 조사에서 실제로 걸린 것만 적는다. 미리 선언하지 않는다. 소스가 어긋났던 지점, 숫자를 잘못 읽을 뻔한 지점이 규칙이 된다.
3. **AI 금지 가정 3~5개.** 소유자의 확증편향을 겨냥한다. 이 대상에서 빠지기 쉬운 함정.
4. **다음 소스 액션.** 날짜나 문서 이름이 박힌 것으로. "더 조사한다"는 액션이 아니다.

끝나면 `context.md`에 옮길 초안을 화면에 보여주고 소유자에게 무엇을 넣을지 고르게 한다. **승인 없이 `context.md`를 고치지 않는다.** (작업실 규칙: `context.md`는 소유자 지시로만 수정)

| context.md의 칸 | 어디서 오나 |
|---|---|
| 지금 보고 있는 것 | 대상 한 줄과 왜 보는지, 지금 상태 |
| 판단 (날짜 + 이유) | 0절과 3절에서 |
| 핵심 질문 | 1번 그대로 |
| 소스 이력 | 8-1절 그대로. "믿기 어려운 점" 열이 그대로 간다 |
| 결정 규칙 / AI 금지 가정 / Unknowns / 다음 소스 액션 | 2, 3, 9절, 4번 |

판단 한 줄은 이 형태로 쓴다: `- (YYYY-MM-DD) 판단: <한 문장>. 이유: <근거 수치와 출처 라벨>`

### 스캔 모드: 돈의 흐름 3문장과 다음 소스

1. **돈이 어디서 들어와 어디로 가는지 3문장.** 메커니즘 중심. 각 문장에 라벨. 라벨을 붙일 수 없는 수치는 문장에서 뺀다.
2. **검색으로 답이 안 나오는 질문 후보 3개.** 1차 소스(원문, 인터뷰, 공시, IR)가 있어야 풀리는 것만. 각 질문에 어떤 1차 소스가 있어야 확인되는지 적는다.
3. **다음 소스 액션.** 날짜나 문서 이름이 박힌 것으로.

저장 후 `context.md`의 "지금 보고 있는 것" 표와 "소스 이력" 표에 반영할지 소유자에게 묻는다.

## 규칙

- 모든 수치와 핵심 주장에 `[1차]` `[2차]` `[추정]` 중 하나를 붙인다. 못 붙이면 쓰지 않는다.
- 확인 안 되는 것은 지어내지 않고 `unknown`으로 적는다. 확인 방법을 한 줄 같이 남긴다.
- 공시, 회사 IR, 공식 홈페이지는 `[1차]`. 언론과 제3자 정리본은 `[2차]`. 계산하거나 미루어 짐작한 것은 `[추정]`.
- 핵심 수치는 두 출처나 두 방법으로 교차한다. 교차 못 하면 단일 출처임을 8-2에 표시한다.
- **연결과 별도를 섞지 않는다.** 섞어야 하면 어느 기준인지 표에 적고 비교 계산에 `[추정]`을 붙인다.
- **고객이 지배주주와 같은 기업집단이면 특수관계자 매출을 뺀 매출을 따로 계산한다.** 총매출 성장률만 보고 판단하지 않는다.
- **시세는 야후, 재무는 공시.** 어긋나면 공시를 쓰고 어긋난 사실 자체를 문서에 적는다.
- 계약 금액은 정정 공시를 확인한 뒤 최신 금액을 쓴다.
- 종목 추천, 목표주가, 기대수익률은 쓰지 않는다. 증권사 리포트의 의견은 그 증권사가 그렇게 냈다는 사실로도 옮기지 않는다.
- 보도 수치가 매체마다 다르면 하나로 합치지 않는다. 둘 다 적고 `unknown`으로 표시한다.

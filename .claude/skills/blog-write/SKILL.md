## 이 스킬은
- 어떤 병목: 사실·수치 확인과 그걸 글로 풀어내는 게 빨리 안 되는 막막함
- 입력 → 남는 것: Notion에 쌓아둔 글감 주제 하나 → 사실 검증까지 끝난 블로그 초안 파일 하나
- 설치 후 첫 실행: "블로그 글 써줘" (라고 치면 AI가 시의성 높은 주제부터 추천하며 시작)

# Blog Write — Notion 주제 → 경제 블로그 초안

Notion에 정리해둔 글감을 바탕으로 경제 블로그 글쓰기 노동을 줄이는 스킬이다. 다만 이 워크스페이스의 절대 규칙(투자 조언 금지, 근거 없는 수치 생성 금지, 출처 라벨)은 블로그 초안에도 그대로 적용된다. 2026-07-23 참가자 지시에 따라, 라벨을 붙이는 것만으로는 부족하고 **AI가 스스로 모든 사실·수치를 재확인하는 루프**를 거친 뒤에만 초안에 남긴다.

## 사전 준비 (최초 1회)

- **Notion 연결**: 이 저장소 세션이 아니라 **claude.ai 계정 설정(Settings → Connectors)** 또는 Claude Desktop에서 Notion을 1회 연결해야 한다. 연결되면 이후 모든 Claude Code 세션에서 Notion MCP 도구(`mcp__notion__*` 형태)가 자동으로 열린다.
- 이 스킬을 실행했는데 Notion MCP 도구가 보이지 않으면, 그 사실을 그대로 알리고 위 연결 방법을 안내한 뒤 **중단한다** (연결 안 된 상태를 다른 방식으로 우회하지 않는다).
- **주제 저장소 지정**: 확정된 글감 저장소는 "투자 / 경제 글 주제 모음" 페이지 — https://app.notion.com/p/33eab743ca8f801fa7eaf24080893866 (2026-07-24 확인, **김지훈님 개인 Notion 페이지**). 참가자가 다른 저장소로 바꾸자고 하면 이 URL을 갱신한다. **이 스킬을 다른 사람이 받아쓰는 경우**, 이 URL은 그 사람 것이 아니므로 반드시 자신의 글감 저장소 페이지 URL로 먼저 교체해야 한다 — 교체 안 하면 실행 전에 그 사실을 알리고 중단한다.
- **문체 가이드(`style.md`)**: 참가자가 기존에 쓴 글 샘플을 주면 그 문체(톤·문장 길이·문단 구성·자주 쓰는/피하는 표현)를 분석해 같은 폴더의 `style.md`에 남긴다 — 추측으로 채우지 않고, 항상 실제 샘플에서만 뽑는다. 샘플이 아직 없으면 `style.md`는 "샘플 미제공" 상태로 두고 기본 문체로 작성한다. 새 샘플이나 교정을 받으면 `style.md`를 갱신한다.
- **밸류체인 연계(선택)**: 산업/섹터 분석형 주제에서는 `.claude/skills/peer-jungjmjj0217-svg-valuechain/`(동료 스킬)를 함께 쓴다. 2단계에서 조건을 판단한다. 이 스킬이 워크스페이스에 없으면 그 사실을 알리고 표 없이 진행할지 확인받는다 — 대신 만들어내지 않는다.
- **사이트 저장소**: 확정된 글을 실제로 올리는 곳은 `https://github.com/jihunx-collab/asset-log` (**김지훈님 개인 GitHub 저장소**, Vercel과 연동돼 push하면 자동 배포됨). **이 스킬을 다른 사람이 받아쓰는 경우**, 이 저장소 URL은 그 사람 것이 아니므로 반드시 자신의 사이트 저장소 URL로 먼저 교체해야 한다 — 교체 안 하면 9단계 실행 전에 그 사실을 알리고 중단한다.

## 절차

### 1. 주제 확정
- 지정된 Notion 저장소를 스캔해 아직 블로그 초안으로 안 옮긴 주제를 찾는다.
- 여러 개면, 최근 이슈·시장 상황과 결부되는 시의성을 기준으로 가장 적합한 1개를 골라 이유와 함께 먼저 추천한다. 참가자가 다른 걸 쓰고 싶다고 하면 나머지 후보도 보여주고 고르게 한다.
- 하나도 없으면 지어내지 않고 그대로 알린다.

### 2. 산업/섹터 밸류체인 선행 (조건부)
- 확정된 주제가 특정 산업/섹터 하나의 구조·플레이어·공급망(업스트림→다운스트림)을 다뤄야 하는 분석형 주제인지 판단한다 (예: "2차전지 산업", "RWA 인프라", "조선업"). 거시·금리·정책·특정 기업 실적처럼 산업 구조 자체가 핵심이 아닌 주제는 해당하지 않는다. 애매하면 참가자에게 확인받는다.
- 해당하면 `peer-jungjmjj0217-svg-valuechain` 스킬을 그 산업명으로 호출한다. 표가 확인되면 이어서 "시각화해줘"에 해당하는 요청으로 그 스킬의 Artifact 발행까지 진행한다 — 이 스킬을 거치는 산업/섹터형 글은 표와 이미지(Artifact)를 함께 남기는 걸 기본으로 한다.
- 그 스킬이 설치돼 있지 않거나 실행에 실패하면 그 사실을 그대로 알리고, 표 없이 진행할지 참가자에게 확인받는다 — 대신 밸류체인을 지어내지 않는다.
- 해당하지 않으면 이 단계를 건너뛰고 3단계로 간다.
- 여기서 만든 밸류체인 표·Artifact URL은 3단계(목차 확정)의 본문 섹션 구성에 반영한다 — 예를 들어 밸류체인 단계 순서를 본문 소제목 순서로 쓸 수 있다.

### 3. 목차(개요) 확정
- 제목 / 서론 / 본문 섹션 구성 / 결론까지, 문장은 채우지 않고 **뼈대만** 잡아 참가자에게 보여주고 확인받는다. 2단계에서 밸류체인을 만들었다면 그 구조를 본문 섹션에 어떻게 반영할지도 함께 보여준다.
- 참가자가 순서·구성을 바꾸자고 하면 반영해 다시 보여준다. 확정 신호를 받기 전에는 4단계로 넘어가지 않는다.

### 4. 본문 작성
- 확정된 목차를 따라 문장을 채운다.
- 같은 폴더의 `style.md`가 "샘플 미제공" 상태가 아니면, 그 가이드(톤·문장 길이·문단 구성·표현)를 따라 문장을 쓴다.
- 2단계에서 밸류체인 표를 만들었다면, 표(또는 표를 요약한 문단)와 Artifact 링크를 관련 섹션에 포함한다.
- 본문에 들어갈 사실·수치는 이 단계에서 채워 넣되, 아직 **미검증** 상태로 취급한다 (라벨을 바로 확정하지 않는다).

### 5. 출처 재확인 루프 (self-verification pass) — 이 스킬의 핵심
- 초안에 들어간 모든 사실·수치 주장을 목록으로 뽑는다.
- 각 주장을 WebSearch/WebFetch(또는 1차 출처: 통계청, 한국은행, FRED, 기업 공시 등)로 하나씩 재대조한다.
- 확인되면 `[1차]`/`[2차]` 라벨을 확정한다.
- 소스 간 불일치하거나 재확인 자체가 안 되면, 라벨을 붙이고 넘어가지 않고 그 문장을 **삭제하거나 `unknown` + 확인 방법으로 대체**한다.
- 밸류체인 표에서 가져온 사실·수치는 그 스킬이 이미 출처 링크와 라벨을 붙여둔 것이므로 다시 검색하지 않고 그대로 가져오되, 출처 확인 로그에 "밸류체인 스킬에서 가져옴 — 원출처 링크"로 남긴다.
- 재확인 결과를 초안 하단에 "출처 확인 로그" 섹션으로 남겨, 무엇을 어떻게 재검증했는지 참가자가 추적할 수 있게 한다.

### 6. 최종 자기 점검
- 라벨 없이 남은 수치·주장이 있는지 스스로 다시 훑는다.
- 매수·매도·목표가·기대수익률 등 투자 조언으로 읽힐 수 있는 문장이 없는지 확인한다.
- 위 두 가지가 모두 정리된 뒤에만 초안을 "완료"로 표시한다.

### 7. 저장 (로컬)
`outputs/blog-drafts/{한글 제목}-YYYY-MM-DD.md`로 저장한다 (디렉터리 없으면 생성) — 파일명은 사이트에 올라갈 글 제목(한글)을 그대로 쓴다. 파일시스템에서 못 쓰는 문자(`/ : * ? " < > |`)만 제거하거나 다른 기호로 바꾸고, 나머지는 그대로 둔다. 제목이 아주 길면 핵심만 남기고 줄여도 된다.

**참고**: 이 한글 파일명 규칙은 `outputs/blog-drafts/`(로컬 초안)에만 적용한다. asset-log 사이트의 `content/posts/` 쪽은 파일명이 곧 URL slug이므로 계속 영문 슬러그(`{slug}-YYYY-MM-DD.md`)를 쓴다 — 사이트에 올릴 때 이 슬러그로 별도 변환한다.

아래 틀을 따른다:

```markdown
# {제목}

## 서론
...

## 본문
...
(2단계에서 밸류체인을 만들었다면, 해당 섹션에 표와 Artifact 링크를 포함한다)

## 결론
...

---

## 출처 확인 로그
- 주장: ...
  - 재확인 방법: ... / 결과: [1차]/[2차]/삭제됨/unknown
```

파일이 이미 있으면 덮어쓰기 전 참가자에게 보여주고 확인받는다. 이후 대화로 수정을 이어가는 동안에는 이 로컬 파일만 계속 갱신한다 — 아직 Google Docs 업로드는 하지 않는다.

### 8. Google Docs 업로드 (수정 다 끝난 뒤, 1회)
참가자가 "이제 됐어" / "완료" / "구글독스로 저장해줘" 등으로 **수정이 다 끝났다는 확정 신호**를 줄 때만, 그 시점의 최종 로컬 파일 내용을 Google Drive "블로그" 폴더(id: `1UddTps52aPFqjU6pyBN3c4KMvBr8G3BU`, **김지훈님 개인 Drive 폴더**)에 Google Docs로 업로드한다. **다른 사람이 이 스킬을 받아쓰는 경우**, 이 폴더 id도 그 사람 것으로 바꿔야 한다 — 모르면 업로드 전에 자신의 Drive에서 저장할 폴더를 확인받는다. (`mcp__claude_ai_Google_Drive__create_file`, `parentId`에 위 폴더 id, `textContent`에 마크다운 본문, `contentMimeType: text/markdown` → Google Docs로 자동 변환됨).

**주의**: 현재 연결된 Drive 도구는 기존 파일을 덮어쓰는 기능이 없고 새로 생성만 가능하다 — 그래서 확정 전에는 업로드하지 않는다. 업로드 후에 참가자가 또 수정을 요청하면, 로컬 파일을 갱신한 뒤 "기존 Google Doc을 다시 확정해서 새로 올릴지(중복 생성됨), 아니면 이번엔 로컬만 갱신할지" 참가자에게 물어본다. 업로드 실패 시(연결 끊김 등)에는 그 사실을 그대로 알리고, 로컬 파일 저장까지는 완료된 상태임을 알린다.

### 9. asset-log 사이트 반영 (Google Docs와 같은 확정 신호, 2026-08-06부터)
8단계와 같은 확정 신호를 받으면, Google Docs 업로드와 함께(또는 참가자가 그중 하나만 원하면 그것만) 로컬 초안을 사이트 저장소에도 반영한다.

- 로컬 클론이 스크래치패드에 없으면 새로 clone한다 (세션마다 스크래치패드가 초기화되므로 매번 새로 받는 게 정상이다).
- 변환 규칙:
  - 파일명: `content/posts/{영문 슬러그}-YYYY-MM-DD.md` — 로컬 한글 제목에서 짧고 명확한 영문 슬러그를 새로 뽑는다(케밥 케이스, 기존 파일명들과 스타일을 맞춘다).
  - frontmatter를 추가한다: `title`(한글 제목 그대로), `date`, `category`(기존 카테고리 중 하나 — 기업분석/대체투자/부동산/산업분석/크립토. 다섯 개 중 안 맞으면 새 카테고리를 쓰기 전에 참가자에게 먼저 확인한다), `tags`(핵심 키워드 3~6개).
  - 본문 최상단의 `# 제목` 줄(H1)은 제거한다 — frontmatter의 `title`이 그 역할을 한다.
  - "출처 확인 로그" 섹션은 지우지 않고 `<details><summary>출처 확인 로그 보기 — 본문의 모든 사실·수치를 어떻게 재검증했는지</summary> ... </details>`로 감싸 접어서 유지한다(2026-08-06 참가자 지시 — 출처는 클릭해야 보이게, `lib/posts.ts`가 이미 `sanitize:false`로 설정돼 있어 `<details>`가 그대로 렌더링된다. 이 설정이 빠져 있으면 먼저 넣는다).
  - 2단계에서 밸류체인 Artifact를 만들었다면, 링크만 남기지 말고 그 사이트의 다크 테마 CSS 변수(`app/globals.css`의 `--color-al-*`)에 맞춘 정적(비-JS) 카드형 다이어그램을 본문에 직접 삽입한다(2026-08-06 지시 — "글에서 바로 파악할 수 있으면 좋겠다"). 시간이 부족하면 최소한 표는 본문에 그대로 남기고, 시각화 삽입 여부를 참가자에게 확인한다.
- 커밋 전에 `npm run lint`, `npm run test`, `npm run build`를 로컬에서 돌려 통과하는지 확인한다. 실패하면 원인을 고치기 전엔 push하지 않는다.
- 이 저장소는 `main`에 직접 커밋하는 게 지금까지의 관례다(커밋 로그로 확인됨, PR 브랜치 없음). 커밋 메시지는 `content: ...` 형식을 따르고 `git push origin main`으로 올린다.
- push하면 Vercel이 자동으로 배포한다 — **이 시점부터 실제 퍼블릭 사이트에 게시된다는 걸 참가자에게 분명히 알린다.** 배포 확인은 WebFetch로 직접 하되, 캐시 때문에 최근 결과가 스냅샷일 수 있다는 점을 함께 알린다.
- 완료 후 실제 라이브 URL을 참가자에게 보고한다.

### 10. 완료 후
`context.md` 소스 이력과 `journey.md` "내가 지은 방들"에 반영할지 참가자에게 물어본다 (강제하지 않는다).

## 원칙

- **투자 조언 금지.** 경제 현상·수치를 기록·설명할 뿐, 매수·매도·목표가·기대수익률을 생성하지 않는다.
- **라벨만으로 끝내지 않는다.** 모든 수치·핵심 주장은 라벨을 붙이기 전에 AI가 직접 재확인하고, 재확인 안 되면 삭제하거나 `unknown` 처리한다.
- **발행은 확정 신호가 있어야만.** 로컬 초안(7단계)까지는 자유롭게 고친다. Google Docs 업로드(8단계)와 asset-log 사이트 반영(9단계, 실제 퍼블릭 배포)은 참가자의 명시적 확정 신호("이제 됐어" 등) 없이는 하지 않는다.
- **크레덴셜 커밋 금지.** Notion 토큰 등은 어떤 파일에도 남기지 않는다.
- **참가자 소유.** `outputs/blog-drafts/`는 참가자의 산출물이다 — 최종 문구는 참가자 확인을 거쳐 확정한다.
- **수동 호출.** 자동 실행되지 않는다. 정기 자동화가 필요해지면 `/schedule` 연계를 별도로 검토한다 (이번 스킬 범위 아님).
